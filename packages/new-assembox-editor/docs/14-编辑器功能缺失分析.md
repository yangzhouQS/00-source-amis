| 模块               | 状态 | 证据                                                                    |
| ------------------ | ---- | ----------------------------------------------------------------------- |
| Editor.ts          | ✅   | schemaOps 驱动全部 mutation；renderer 从 profile.createRenderer() 创建  |

### 🟠 P1：核心功能缺失

| #   | 缺失                                      | 说明                                                                                               | 参考                                | 状态                                                                                                                                                                                                                      |
| --- | ----------------------------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4   | ~~**iframe 渲染器 reactive 桥接未验证**~~ | ~~PcIframeRenderer 的 schema 是否同引用穿透到 iframe 内的 AssemCore~~                              | 设计文档 P0-1                       | ✅ **不适用**：iframe 是独立浏览上下文，无法共享 JS 对象引用。当前走显式同步（syncRenderer → setSchema 推送），是 iframe 模式的正确做法。同 DOM 模式天然 reactive（AssemCore 持有同一引用，Phase 0.5 已确认）。此项移除。 |
| 5   | ~~**属性面板无 setter 动态加载**~~        | ~~catalog 的 props 配置全靠手动维护（component-metadata.ts），manifest.ts 加新属性时编辑器不感知~~ | 长期目标：manifest 导出运行时元数据 | ✅ **不适用（设计决策）**：渲染库新增组件后，编辑器必须手动添加组件属性配置并进行测试。属性元数据（scaffold + setter 映射）是编辑器专属知识，不应自动同步——需要人工验证 setter 适配、默认值、分组等。此项移除。           |
| 6   | ~~**嵌套校验未接入拖拽**~~                | ~~Dragon onDrop 直接 insert，未校验 `nestingRules.canNest`~~                                       | editor.ts wireDragon 加校验         | ✅ 已修复：两层校验（CanvasSensor.locate 拖拽中视觉拒绝 + editor.wireDragon onDrop 最终拦截）；dragon.dragObject 改 public 供 CanvasSensor 读取                                                                           |
| 7   | **空容器拖入体验缺失**                    | 空的 FlexBox itemConfig[].defaultSlot = null 时，拖入组件无法识别为有效投放目标                    | CanvasSensor + schemaOps 特殊处理   | ⬇️ 降级 P2：功能已通（schemaOps.insertNode 处理 null defaultSlot）；仅体验缺失（空区域无高度/无占位提示/无槽位标记）。后续优化：容器组件加空占位 div + min-height + 槽位标记。                                            |
| 8   | **大纲树不支持操作**                      | 当前大纲只读（展示树结构），不支持点击选中、拖拽排序、右键删除                                     | outline-pane 增强                   |

### 🟡 P2：体验优化

| #   | 缺失                  | 说明                                                                                        |
| --- | --------------------- | ------------------------------------------------------------------------------------------- |
| 9   | **撤销/重做性能**     | snapshot-based history 对大 schema（1000+ 节点）每次 commit 深拷贝 → 卡顿。应改 patch-based |
| 10  | **无代码导出**        | 无法将编辑结果导出为可部署的 JSON / Vue SFC / HTML                                          |
| 11  | **无多文档支持**      | PC 场景的 Dialog/Drawer 各有独立 schema，当前只操作单一 schema 树                           |
| 12  | **无响应式预览**      | 设备预设（手机/平板）只改 iframe 宽度，不切换移动端渲染库                                   |
| 13  | **无组件搜索高亮**    | 搜索过滤后无匹配项高亮、无键盘导航（↑↓选中 + Enter 插入）                                   |
| 14  | ~~**无自动保存 / 草稿**~~ | ~~编辑结果不持久化，刷新丢失~~ | ✅ 已修复：sessionStorage 草稿自动保存（debounce 800ms + beforeunload 兜底）；刷新恢复（constructor 读 draft → loadSchema）；clearDraft() 显式清除；关标签页自动清除（sessionStorage 特性） |
| 15  | **事件编辑器简陋**    | EventList 只有 actionType 下拉 + 简单 input，缺少条件编排（if/else）、循环、并行等控制流    |
