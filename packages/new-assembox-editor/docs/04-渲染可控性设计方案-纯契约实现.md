# 渲染可控性设计方案（修正版·纯契约实现）

> 本文为头脑风暴压力测试后的**修正版设计**，取代 `02-渲染可控性可行性方案.md` 中「缝增强需改 assembox-desktop」的判断。
> 核心修正：`assembox-desktop` **零源码改动**，编辑器通过实现既有 `AssemVueRenderer` 契约获得全部控制能力。

---

## 一、背景与硬约束

1. 生产已大面积使用，存量模块 **500+**；
2. 编辑器必须复用 `assembox-desktop` 渲染（保证编辑态 == 生产态，杜绝两套渲染漂移）；
3. 编辑器仅开发期使用，生产运行时只用 `assembox-desktop`；
4. `assembox-desktop`/`assembox-core` 可改但需灰度（本方案实测**无需改**）。

---

## 二、头脑风暴关键发现（修正原判断）

### 2.1 缝是「集中式」，不是「散落」

- `compsInit()`（`hook/init-hook.ts:28`）被**全部 76 个渲染组件**调用（元素/容器/布局/业务组件）；
- `compsInit()` → `editorHook()`（`hook/editor-hook.ts:15`）；
- `editorHook()` 在 `isEditorEnv()` 时把每个节点实例上报到 `window.AssemVueRenderer.onMountedInstance(instance)`。

> 注入点是**一个函数**，非 20+ 文件。新增组件只要调 `compsInit()` 即自动接入。

### 2.2 `AssemVueRenderer` 是既有契约，无需新建 design-hooks

`assembox-desktop` **已在**编辑环境下向 `window.AssemVueRenderer` 上报节点生命周期：

```ts
// hook/editor-hook.ts（既有，无需改）
onMounted(()  => { if (isEditorEnv()) win.AssemVueRenderer.onMountedInstance(getCurrentInstance()); });
onUpdated(()  => { if (isEditorEnv()) win.AssemVueRenderer.onUpdatedInstance(getCurrentInstance()); });
onUnmounted(() => { if (isEditorEnv()) win.AssemVueRenderer.onUnmountedInstance(getCurrentInstance()); });
```

`isEditorEnv() = window.assemBoxIsEdit`（生产恒 `false` → 上报不执行 → 生产零开销）。

→ **编辑器只需在 iframe 内实现 `window.AssemVueRenderer` 这个契约**，即可拿到每个节点的 Vue 实例（含 `$el` + `props.__nodeId/__nodeName/__nodeType/__nodeOptions`），进而盖标记、建树、取几何、做选区。**assembox-desktop 源码零改动。**

### 2.3 差异化重渲染不必动生产 `:key`

- **属性变更**：`assembox-desktop` 的 props 本就 reactive，编辑器就地改深路径 → 该组件自动局部重渲染；
- **结构变更**（增删移）：子树 remount，**编辑期可接受**；
- 真正要消除的是「`:key=refrash` 全页重建」（编辑器自身策略），与 `assembox-desktop` 无关。

→ `assembox-desktop` 的 `:key` 改动**完全去掉**，生产路径更干净。

## 三、架构设计

```
┌─ 编辑器（new-assembox-editor，仅开发期） ────────────────────────────┐
│  Workbench / 组件面板 / 属性面板 / 大纲 / BemTools / Dragon           │
│  IframeBridge ──直引/postMessage──┐                                  │
└───────────────────────────────────┼─────────────────────────────────┘
                                     ▼
┌─ iframe 画布（canvas.html）─────────────────────────────────────────┐
│  window.assemBoxIsEdit = true                                       │
│  window.AssemVueRenderer = editorBridge   ← 编辑器实现既有契约       │
│  挂载 assembox-desktop（AssemPlugin + views）渲染 JSON               │
│     │  渲染行为与生产完全一致                                         │
│     ▼                                                                │
│  每节点 mount → compsInit() → editorHook() → editorBridge.onMountedInstance(instance)
│     编辑器侧处理：                                                    │

└─────────────────────────────────────────────────────────────────────┘

生产：不设 assemBoxIsEdit → isEditorEnv()===false → 上报不执行 → assembox-desktop 走纯渲染原路径（零改动、零风险）
```

## 四、`AssemVueRenderer` 契约 API（编辑器侧实现）

```ts
/** 编辑器在 iframe 内实现的契约（assembox-desktop 既有调用方） */
interface AssemVueRenderer {
  /** 节点挂载：assembox-desktop 在 isEditorEnv 时调用，传入节点 Vue 实例 */
  onMountedInstance(instance: ComponentInternalInstance): void;
  /** 节点更新 */
  onUpdatedInstance(instance: ComponentInternalInstance): void;
  /** 节点卸载 */
  onUnmountedInstance(instance: ComponentInternalInstance): void;
}
```

### 编辑器侧从 instance 提取的信息

| 信息 | 取法 | 用途 |
|---|---|---|
| 根 DOM | `instance.proxy.$el`（校验 nodeType） | 盖 `data-editor-id`、几何测量 |
| 节点 id | `instance.props.__nodeId` | 身份匹配（可能重复，见 §5） |
| 节点名/类型 | `instance.props.__nodeName / __nodeType` | 过滤 renderNode/columnNode、大纲展示 |
| 节点配置 | `instance.props.__nodeOptions` | 属性面板读写、就地变更 |
| 节点事件 | `instance.props.__nodeEvent` | 事件面板 |
| 父节点 | `$el.parentElement.closest('[data-editor-id]')` | 建树、region 判定 |

> 过滤：仅处理 `__nodeType === 'baseNode'`（实际组件），跳过 `renderNode`/`columnNode`（派发包装）——与 `compsInit` 内 `setExposed` 的过滤逻辑一致。

## 五、`$$eid` 身份匹配算法（解决 `__nodeId` 重复）

`__nodeId` 大量重复（box.json 19 个仅 13 个唯一），不能直接用于选区/key。引入**编辑态唯一标识 `$$eid`**，**不动 `__nodeId`/`$exposeds`**（生产兼容）。

### 5.1 加载期：预分配 + 结构索引

```
loadJson(file)
  → deepClone（永不改文件）
  → walk(clone): 每个节点赋 $$eid = 'e_' + base36(自增) + 短随机   // 全局唯一
  → 记录结构索引：Map<$$eid, {nodeRef, parent$$eid, region, depth, orderInParent}>
  → __nodeId / $exposeds 原样保留
  → 喂给 assembox-desktop 渲染
```

### 5.2 挂载期：实例 ↔ $$eid 匹配（核心）

assembox-desktop 按树深度优先顺序挂载，`onMountedInstance` 依此触发。匹配策略（从稳到松）：

```
onMountedInstance(instance):
  const el = instance.proxy.$el
  const nid = instance.props.__nodeId
  // 1) 父链匹配：用 el 的 DOM 父链找到已登记的 parent$$eid
  const parent$$eid = el.parentElement?.closest('[data-editor-id]')?.dataset.editorId
  // 2) 在「同 parent + 同 __nodeName + 同 depth」的待匹配槽中，取下一个未占位
  const slot = pendingSlots[parent$$eid][nid][nodeName].shift()
  const $$eid = slot?.$$eid ?? fallback()
  // 3) 登记
  el.setAttribute('data-editor-id', $$eid)
  nodeTree.set($$eid, { el, nodeRef: slot.nodeRef, parent$$eid, instance })
```

- **稳态**：结构未变 → 挂载顺序确定 → 精确匹配；
- **异步/条件渲染**致顺序不确定时：用 `__nodeName + __nodeOptions` 内容指纹二次校验；
- **仍失败**：降级到 §8 的 fallback（$$eid 注入透传，仅改 2 个派发器）。

### 5.3 保存期

```
exportJson():
  → walk(workingClone): 剔除 $$eid
  → __nodeId / __nodeOptions / __nodeEvent / $exposeds 结构原样输出
  → 生产可直接读取（无任何兼容字段）
```

## 六、编辑器控制能力映射

| 能力 | 实现方式（纯契约） |
|---|---|
| 节点标记 | `onMountedInstance` → `el.setAttribute('data-editor-id', $$eid)` |
| 节点树镜像 | `onMountedInstance` 建树；`onUnmountedInstance` 注销 |
| 选中 | iframe doc 捕获阶段 click → `closest('[data-editor-id]')` → 选区（可 `stopPropagation` 拦截节点自身事件） |
| 悬浮高亮 | iframe doc 捕获阶段 mouseover/mouseleave |
| 几何（BemTools） | `nodeTree.get($$eid).el.getBoundingClientRect()` |
| 差异化更新（属性） | `$$eid→nodeRef` 索引 → 就地响应式改 `nodeRef.__nodeOptions.x` → 该组件局部重渲染 |
| 结构变更（增删移） | 改 JSON 深路径 → 子树 remount → `onMountedInstance` 自动重建节点树（可接受） |
| 拖拽投放 | 复用 Dragon + CanvasSensor；落点经 `data-editor-id` + 父链解析容器与 index |

## 七、差异化重渲染策略

| 场景 | 策略 | 效果 |
|---|---|---|
| 改属性（文字/类型/样式） | 就地响应式改 `nodeRef.__nodeOptions.xxx` | 仅该组件重渲染，**不闪全屏** |
| 改事件 | 就地改 `nodeRef.__nodeEvent` | 同上 |
| 插入/删除/移动节点 | 改 JSON 结构 → 子树 remount | 节点树经 `onMountedInstance` 自动重建 |
| 切页面/路由 | assembox-desktop 自有 `:key=refrash`（保留） | 与生产行为一致 |

> 关键：编辑器**绝不**自造全页 `:key` 重建；属性走响应式，结构走 remount。

## 八、风险与对策

| # | 风险 | 等级 | 对策 |
|---|---|---|---|
| 1 | **$$eid 身份匹配脆弱**（异步/条件渲染致挂载顺序错位） | 中 | ① 父链+内容指纹匹配；② 实测若错位 → **降级 fallback**：加载时把 `$$eid` 写进节点，并让 `container-render`/`element-render` 透传 `:__nodeEid`（**仅 2 个派发器门控改动**），onMounted 直接读 `instance.props.__nodeEid`，身份绝对可靠 |
| 2 | **`$el` 不可靠**（setup 多根/fragment 时为注释节点） | 中 | 盖标记前校验 `el.nodeType === 1`；否则回退取 `instance.subTree` 首个真实元素 / `el.nextElementSibling` |
| 3 | **编辑期事件执行**（button @click 跑事件 fn 可能调 API） | 中 | 设计态：iframe doc 捕获阶段 `stopPropagation` 拦截；预览态：放行。若需更彻底，后续给 assembox-desktop 加 1 行 `isEditorEnv` 事件门（可选） |
| 4 | **结构变更子树 remount** | 低 | `onMountedInstance` 自动重建；编辑期可接受 |
| 5 | **自定义组件未调 compsInit** | 低 | 全部 76 个已调；约定新组件必须调（lint/文档） |

### Fallback（$$eid 注入透传）—— 仅在风险 1 实测触发时启用

```vue
<!-- container-render.vue / element-render.vue 门控增量（isEditorEnv 时） -->
<component :is="current" :__node-eid="..." ... />
```
改动量：2 文件 ~16 LOC，`isEditorEnv` 门控，生产不执行。作为纯契约方案的**安全网**。

## 十二、最终判定

- **合理可行**：✅ 高。缝是既有契约，编辑器侧实现即可，渲染与生产绝对一致。
- **成本**：~8.8 工时日，**assembox-desktop 零改动，500+ 模块零风险**。
- **风险**：整体低；主风险（$$eid 身份匹配）有 content-fingerprint + fallback 双保险。
- **可回滚**：编辑器独立包，全程无不可逆操作。

**与原 `02`/`03` 方案的关键差异**：原方案需门控改 assembox-desktop（124 LOC），修正后**完全不动共享库**——这是 500+ 模块场景下最安全的形态；若 V3 验证身份匹配不稳，再以 16 LOC 门控 fallback 兜底，进退皆有据。
