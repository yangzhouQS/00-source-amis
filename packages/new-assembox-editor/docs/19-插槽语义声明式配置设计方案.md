## 1. 问题：宿主槽位知识散落五处

近几轮修复（YqToolBar.defaultSlot 崩溃、YqFilterItem 数组化、isContainer 穿透）
陆续引入了硬编码表，槽位语义没有单一真相源：

| 文件 | 承载知识 | 形态 | 问题 |
|---|---|---|---|
| `scenarios/pc-desktop/slot-accessors.ts` DIRECT_SLOTS | 槽位字段名（全局） | 数据 | 合理保留 |
| `slot-accessors.ts` SINGLE_NODE_SLOTS | 7 个宿主单节点语义 | **硬编码** | 加组件要改代码 |
| `scenarios/pc-desktop/nesting-rules.ts` SLOT_GATE_OVERRIDES | Toolbar defaultSlot 门禁 | **硬编码** | 同上 |
| 渲染库 `nesting.ts` SLOTS | category 级门禁 | 数据 | 语义混渲染期校验，编辑器特化不能进（用户约束） |
| `scenarios/pc-desktop/slot-dom/` | DOM 几何识别 | 代码 | 正交，合理保留 |

新增组件槽位语义需动 3~4 处代码；`component-metadata-config/` 已建立
"元数据集中声明"模式（props/events/methods/scaffold），**slots 是缺失的最后一块**。

### category 门禁的粒度缺口（声明式的直接动机）

`YqToolBar.defaultSlot` 门禁现为 `['layout']`（category 级），会放行
GridBox / YqFlexBox——但 wrapper（assem-yq-tool-bar.vue:31-41）**硬编码只认
单个 AssemYqFlexLine**。旧版 `slotRender: ["flexLine"]` 是组件级白名单，
精确闭合此缺口。

## 2. 方案：元数据声明 slotConfig

### 2.1 类型定义（scenario/types.ts）

```ts
/** 槽位语义声明（宿主维度，数据驱动） */
export interface ComponentSlotConfig {
  /** 槽位键（slot-accessors DIRECT_SLOTS 键：defaultSlot/toolSlot/...） */
  name: string;
  /** object = 单节点（wrapper :node 直渲）；array = 数组（v-for 消费） */
  slotType: "object" | "array";
  /** 组件级白名单（renderType，精确匹配）；缺省回落 category 门禁 */
  slotRender?: string[];
  /** 槽位显示名（大纲树 getNodeSlots label / 未来占位文案的单一来源） */
  description?: string;
}

export interface ComponentCatalogItem {
  // ...现有字段
  slots?: ComponentSlotConfig[];
}
```

### 2.2 声明示例（component-metadata-config/block-container.ts）

```ts
// YqToolBar：三槽全部声明
slots: [
  {
    name: "defaultSlot",
    slotType: "object",                        // wrapper 直渲单个 FlexLine
    slotRender: ["YqFlexLine"],                // 组件级白名单（比 ['layout'] 精确）
    description: "默认插槽",
  },
  { name: "toolSlot",  slotType: "array", slotRender: ["Button", "YqAdvancedFilter", "Dropdown"], description: "工具栏插槽" },
  { name: "filterSlot", slotType: "array", slotRender: ["YqFilterItem"], description: "过滤器插槽" },
]
```

其余单节点宿主（声明 slotType 即可，白名单缺省走 category 门禁）：

```ts
YqFilterItem:  slots: [{ name: "defaultSlot", slotType: "object", slotRender: ["Input","Select","DatePicker","YqDateRangePicker","TimePicker","YqSearchSelect","YqSearchTreeSelect","YqDictionarySelect","Switch","InputNumber","YqBasisCommonSelectApi"], description: "筛选控件" }]
FormItem:      slots: [{ name: "defaultSlot", slotType: "object", description: "表单控件" }]
GridItem:      slots: [{ name: "defaultSlot", slotType: "object", description: "内容区" }]
Dialog / Drawer: slots: [{ name: "defaultSlot", slotType: "object", description: "内容区" }]
YqNavigationBar: slots: [{ name: "defaultSlot", slotType: "object", description: "工具区" }]
```

数组槽宿主（YqPanel/YqBox/Form/GridBox/YqFlexLine）同样声明
`slotType:"array"` 使语义显式化（当前靠"不在 SINGLE_NODE_SLOTS 表"隐式表达）。

## 3. 旧版字段映射

| 旧版字段 | 新落点 | 迁移决策 |
|---|---|---|
| `slotType: "object"/"array"` | 单节点分支（insertChildIntoOpts / canInsertIntoSlot / canvas-sensor 1.7） | **迁移**，替换 SINGLE_NODE_SLOTS |
| `slotRender: ["flexLine"]` | canNest 组件级白名单优先，category 门禁兜底 | **迁移**（注意用新 renderType 名 `YqFlexLine`） |
| `description` | getNodeSlots label / 占位文案 | **迁移** |
| `initialValue()`（插入自动造壳） | 新版 scaffold 默认值机制已覆盖（toolbar scaffold 自带 FlexLine） | **不迁移** |
| `removeInitialValue()`（删后置 null） | removeChildFromOpts 单节点分支已有（opts[field] = null） | **不迁移** |
| `el.__assembox$slotType` 打标 | 新版几何解析（slot-dom/）替代，无需 DOM 标记 | **不迁移** |

## 4. 依赖方向与注入设计

### 4.1 约束

`slot-accessors.ts` 是**纯函数模块**（无 catalog/editor 访问能力，可独立测试）；
元数据在 catalog。不能让 slot-accessors 反向依赖场景层（会成环）。

### 4.2 启动时编译 + 模块级注册点

```
component-metadata-config（声明 slots）
  → buildSlotSemantics(catalog.getComponents())        // 纯函数，一次编译
      产出 {
        singleNodeSlots: Record<宿主renderType, 槽位name[]>
        slotWhitelists: Record<"宿主::槽位", renderType[]>
        slotDescriptions: Record<"宿主::槽位", string>
      }
  → setSlotSemantics(semantics)                        // 注入 slot-accessors 模块级注册点
```

- 新文件 `scenarios/pc-desktop/slot-semantics.ts`：buildSlotSemantics + 类型
- `slot-accessors.ts` 增模块级变量 + setter；`isSingleNodeSlot` 等改为
  查注入表 → **未注入时回落现有硬编码表**（渐进迁移的兼容层）
- 注入时机：`pcDesktopProfile` 首次使用（构造 PcSchemaOps 时）或 editor
  初始化时——保证任何 schemaOps 调用前完成

### 4.3 canNest 白名单优先级

```
canNest(parent, slotKey, child):
  1. slotWhitelists["parent::slotKey"] 存在 → 白名单精确匹配（含/不含）
  2. 否则 → 现 category 门禁链（OVERRIDES → 渲染库 SLOTS）
```

`SLOT_GATE_OVERRIDES`（YqToolBar.defaultSlot:['layout']）在 Toolbar 声明
slotRender 后可删除（白名单更严且更准）。

| 消费端 | 改动 | 兼容性 |
|---|---|---|

## 6. 边界与风险

| # | 风险 | 对策 |
|---|---|---|
| 1 | **声明与 wrapper 实际行为漂移**（slotType:"array" 但 wrapper 直渲 → 崩） | 声明逐条对照 wrapper 源码；SINGLE_NODE_SLOTS 注释中 7 处行号即核对清单；slot-accessors.test.ts 行为守护保留 |
| 2 | **渲染库零改动约束** | slotConfig 仅编辑器侧消费（与旧版一致）；渲染库 SLOTS 保留做渲染期 category 兜底 |
| 3 | **slotRender 遗漏合法子组件**（比 category 门禁收得更紧） | Toolbar defaultSlot 只认 YqFlexLine 是**有意收紧**；filterSlot/toolSlot 白名单从 demo JSON + 组件用途推导，先宽后收 |
| 4 | **注入时序**（schemaOps 先于注入被调用） | 注入放 profile 构造路径（编辑器启动即完成）；单测显式注入构造数据不依赖时序 |
| 5 | **未声明组件回退路径** | 未声明 → 现行为完全不变（category 门禁 + 无单节点语义），逐组件迁移无大爆炸 |
| 6 | **大纲树/占位文案联动**（description 消费） | 低优先级，二期 |

## 7. 渐进式实施计划

| 阶段 | 内容 | 验证 |
|---|---|---|
| **P1 行为等价** | 类型 + buildSlotSemantics + setSlotSemantics 注入 + 7 个单节点宿主声明 slotType（不声明 slotRender） | 现有 34 测试全绿（等价重构）；浏览器回归 YqToolBar/YqFilterItem 拖拽两场景 |
| **P2 白名单收紧** | Toolbar 三槽声明 slotRender；canNest 白名单优先级；删 SLOT_GATE_OVERRIDES | 新增测试：GridBox 拖 Toolbar defaultSlot 被拒（修复 category 粒度缺口） |
| **P3 全量声明** | 数组槽宿主补声明；删 SINGLE_NODE_SLOTS 硬编码表；slot-dom 注释补"与 slots 声明同源"提示 | 全量测试 + 守护测试改造（对齐 slots 声明而非硬编码表） |
| **P4（二期）** | description 消费（大纲树/占位文案）；slotRender 与 component-metadata-config 新组件联动检查 | 视需要 |

## 8. 验收标准

1. **等价性**：P1 后所有既有行为不变（34 测试 + 浏览器两场景回归）
2. **精确性**：P2 后 `canNest("YqToolBar","defaultSlot","GridBox") === false`
   （当前 category 门禁误放行）
3. **单一来源**：P3 后 SINGLE_NODE_SLOTS / SLOT_GATE_OVERRIDES 两张硬编码表删除，
   槽位语义唯一定义在 component-metadata-config
4. **可维护性**：新增多槽位组件 = 元数据一处声明（slots）+ slot-dom 一个
   resolver 文件，零核心逻辑改动
5. **测试守护**：slot-accessors.test.ts / nesting-categories.test.ts /
   slot-dom.test.ts 全绿，且断言基于声明数据而非实现细节

## 附：与旧版实现的差异说明

- 旧版 slotConfig 挂在 `configure`（componentMeta），新版挂在
  `ComponentCatalogItem.slots`（component-metadata-config 目录，按组件分类文件维护）
- 旧版 `initialValue/removeInitialValue` 承担"插入自动造壳/删后清理"，
  新版由 scaffold 默认值 + removeChildFromOpts 单节点分支分别覆盖，不在声明内重复
- 旧版 drag-common.ts 按 slotRender 递归展开**子组件集合**驱动面板过滤，
  新版只做**白名单校验**（面板过滤走 category 体系，属另一话题）
