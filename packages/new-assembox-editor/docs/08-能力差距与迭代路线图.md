# 能力差距与迭代路线图

> 定位：new-assembox-editor 从"结构编排器"迈向"低代码平台"的能力盘点与演进规划
> 依据：对标 amis-editor / lowcode-engine（详见 `04-lowcode插件设计借鉴分析.md` / `05-lowcode物料meta设计借鉴分析.md` / `06-amis插件系统设计借鉴分析.md`）
> 基线：已完成插件体系重构（definePlugin 实例级 + P0/P1/P2 修复）、Dragon 拖拽、iframe 画布、setter 系统、assembox-desktop 契约集成

---

## 一、当前能力现状（已有的）

| 能力域 | 已具备 |
|---|---|
| 核心 | Editor 门面、EditorStore（响应式 + 历史）、EventBus（camelize 映射）、DI、Selection、NodeTree（父子索引） |
| 插件系统 | definePlugin 工厂 + PluginManager（实例级 register/dep 拓扑/contributes 自动应用/setup dispose 回收/activate 幂等/reload 动态激活/priority 覆盖/setup 失败隔离） |
| 骨架 | Skeleton（7 area + Widget/Panel/PanelDock） |
| 物料 | ComponentRegistry（register/weight 覆盖/装饰器自注册）、ComponentMeta（props/PropConfig/regions/events/scaffold） |
| Setter | 25 个（String/Bool/Number/Select/Radio/Json/Array/Object/Icon/Color/Function/Variable…） |
| 画布 | iframe 隔离渲染 + inline、Dragon 自模拟拖拽（跨 iframe）、CanvasSensor（横/竖指示线）、BemTools（iframe offset 换算） |
| Schema | operations 纯函数 CRUD、types |
| 内置面板 | 组件库 / 大纲 / 源码（纯 JSON）/ 设置 / 历史 |
| 动作 | ActionRegistry（声明式动作 + runActions，重名告警） |
| 资产 | AssetRegistry（JS/CSS 注入 iframe） |
| 契约集成 | assembox-desktop（EidRegistry / AssemboxBridge） |
| 测试 | vitest 单测（21）+ playwright e2e（2） |

**结论**：结构编排能力扎实，但**数据驱动层完全缺失**——这是从"编辑器"到"低代码"的关键缺口。

---

## 二、能力差距梳理（按域）

### 🔴 数据与状态层（最大缺口）

| 能力 | 现状 | 成熟方案参考 | 影响 |
|---|---|---|---|
| 公式引擎 `${}` | ❌ 缺失 | amis-formula（lexer→parser→Evaluator，纯 TS） | 一切表达式的基础 |
| 变量系统（页面/全局/临时） | ❌（仅 VariableSetter UI，非数据层） | amis globalVar / lowcode state | 无法存运行时状态 |
| 数据源（API/静态/变量） | ❌ 缺失 | amis DSBuilder / lowcode dataSource | 无法接后端数据 |
| 数据作用域（变量查找链） | ❌ 缺失 | amis `__super` 原型链 / lowcode scope | 子节点读不到父数据 |
| 表达式属性 visibleOn/disabledOn | ❌ 缺失 | amis xxxOn 约定 + getExprProperties | 无法条件显隐/禁用 |

> 不补这层，项目只能搭静态结构，做不出任何"数据驱动"页面（列表/表单/联动）。

### 🟠 交互与联动层

| 能力 | 现状 | 缺口 |
|---|---|---|
| 动作执行引擎 | ✅ ActionRegistry.runActions | 已有引擎 |
| 事件动作可视化编排 | ❌ 缺失 | 无 EventControl 编排 UI（amis 范式） |
| 组件间通信 | ❌ 缺失 | 无 Scoped（reload/send/close，按 name/id） |
| 表达式编辑器 | ❌ 缺失 | 无公式输入 + 字段联想 UI |
| 属性联动 | ❌ 缺失 | A 变化触发 B |

### 🟡 物料表达力（meta 层，详见 05）

- PropConfig 缺：`condition` 条件联动、属性分组嵌套、`supportVariable`、虚拟属性 `getValue/setValue`、嵌套点路径、MixedSetter
- ComponentMeta 缺：snippets 多预设、nestingRule 嵌套约束、supports 能力开关、onNodeAdd 回调、npm 映射

### 🟡 编辑体验

| 能力 | 现状 |
|---|---|
| 组件面板搜索 | ❌ 缺失 |
| Monaco 源码编辑（高亮/校验/双向） | ❌（schema-pane 纯 JSON 文本） |
| 设备尺寸/响应式预览 | ❌（仅 platform 标识） |
| 快捷键（复制/粘贴/删除/移动/撤销） | ❌ 缺失 |
| 区块/模板复用 | ❌ 缺失 |
| 错误边界（防白屏） | ❌ 缺失 |
| 自由布局/磁吸/对齐线 | ❌（仅流式拖拽） |

### 🟢 规模化与产物

| 能力 | 现状 |
|---|---|
| 多页面/多窗口/视图管理 | ❌（单文档） |
| 预览态/运行态分离 | ❌（编辑器直渲染，无 __designMode） |
| 出码（schema→Vue SFC/HTML） | ❌ 缺失 |
| schema 校验（配置合法性） | ❌ 缺失 |
| 性能（大 schema） | ⚠️ getNodeById 全树 DFS、历史全量 clone ×50 |
| i18n | ❌ 缺失 |
| 协同/权限 | ❌ 缺失 |

## 三、迭代路线图（分阶段）

> 原则：**数据驱动优先（让编辑器"活"）→ 交互联动 → 编辑体验 → 规模化 → 产物**。阶段三四可与一二穿插并行。

### 阶段一：数据驱动基础 ★最高优先级（1-2 月）

**目标**：从静态结构编排升级到数据驱动。

| 序 | 任务 | 依赖 | 产出 |
|---|---|---|---|
| 1.1 | 引入 amis-formula 公式引擎 | — | `${}` 表达式求值（registerFunction/filter 可扩展） |
| 1.2 | 变量系统：schema 加 `variables`，Store 维护变量态 | 1.1 | 页面/全局变量读写 |
| 1.3 | 数据源：schema 加 `dataSource`，DSBuilder 抽象（API/静态/变量） | 1.2 | 接口数据加载 |
| 1.4 | 数据作用域：节点级 data scope（原型链查找） | 1.1 | 子节点继承父数据 |
| 1.5 | 表达式属性：visibleOn/disabledOn 渲染前求值 | 1.1 | 条件显隐/禁用 |

**里程碑**：能配置"表格数据源 = API 接口 + 按钮根据变量条件显隐"。

### 阶段二：交互联动（1 月）

| 序 | 任务 | 依赖 |
|---|---|---|
| 2.1 | 事件动作编排 UI（settings-pane"事件"页签，EventControl 范式） | 阶段一 |
| 2.2 | 组件间通信 Scoped（reload/send/close，按 name/id） | 1.4 |
| 2.3 | 表达式编辑器（公式输入 + 字段联想） | 1.1/1.2 |
| 2.4 | 属性联动配置（A→B） | 1.1 |

**里程碑**：能做"提交按钮→调接口→成功 toast→关闭弹窗"完整交互流。

## 四、关键判断

1. **数据驱动层（阶段一）是分水岭**：没有它只是"可视化搭页面工具"，有了它才是"低代码平台"。ROI 最高，必须先做。
2. **公式引擎是阶段一基石**：变量/数据源/条件/联动全部依赖表达式求值。**amis-formula 可直接引入**（纯 TS、框架无关、含 lexer/parser/Evaluator/registerFunction/filter），避免重造轮子（06 文档 P1-5）。
3. **编辑体验（阶段三）可并行**：搜索/Monaco/快捷键/设备预览相互独立，与数据层解耦，可穿插推进，快速提升用户感知。
4. **出码/协同（阶段五）视业务模式**：若产物是"运行时渲染 schema"（amis 模式），出码可不做；若需交付源码则必要。协同属大型团队需求，非必需。
5. **物料 meta 表达力（阶段四）随组件增多再补**：组件少时 PropConfig 够用，复杂组件（表格/表单）多了再补 condition/虚拟属性/MixedSetter。

## 五、优先级速查

```
必做（让编辑器变低代码）：
  阶段一 数据驱动（公式引擎→变量→数据源→作用域→表达式属性）

应做（让交互完整）：
  阶段二 交互联动（事件编排→组件通信→表达式编辑器）

并行（提升体验）：
  阶段三 编辑体验（搜索→Monaco→快捷键→设备预览→错误边界）

按需（规模化）：
  阶段四 物料 meta + 多页面 + 性能 + 校验

远期（产物生态）：
  阶段五 预览分离 + 出码 + 区块 + i18n + 协同
```
