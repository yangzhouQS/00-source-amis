# 实施方案与成本审核（500+ 存量模块版）

> 前提：生产已大面积使用，存量模块 **500+**。最高优先级 = **生产路径 100% 不变、零回归风险**。
> 本文给出逐文件改造清单、工时、风险、不可逆性，供审核。

---

## 〇、关键发现：编辑器缝已存在 → 成本/风险大降

`assembox-desktop` **已有**编辑环境门控与节点上报机制（旧编辑器在用）：

```ts
// hook/editor-hook.ts（已存在）
export const isEditorEnv = () => (window as any).assemBoxIsEdit;   // 生产恒 false
export const editorHook = () => {
  onMounted(() => { if (isEditorEnv()) win.AssemVueRenderer.onMountedInstance(getCurrentInstance()); });
  onUpdated(() => { if (isEditorEnv()) win.AssemVueRenderer.onUpdatedInstance(...); });
  onUnmounted(() => { if (isEditorEnv()) win.AssemVueRenderer.onUnmountedInstance(...); });
};
```

**意义**：
- `isEditorEnv()` 门控已验证可靠（旧编辑器长期使用）；
- 我们只需**增强**该缝为「可控设计钩子」，**不是从零新建**；
- 生产 `isEditorEnv()===false` → 增强代码完全不执行 → **生产路径与现状字节级一致**。

> 结论：500+ 模块、`assembox-desktop` 生产路径 **零改动、零风险**。所有编辑器能力都在 `isEditorEnv()` 门后。

## 二、核心设计：`$$eid` 方案（不动生产语义）

为彻底规避「`__nodeId` 重复 + `$exposeds.get(id)` 引用」对生产的破坏，编辑器引入**独立编辑态唯一标识 `$$eid`**：

```
编辑器加载 single-table.json
  → 深拷贝（永不改文件）
  → 遍历每个节点赋 $$eid = 'e_' + 短随机 + 自增（全局唯一）
  → 建 Map<$$eid, {nodeRef, path, parent$$eid, region}>
  → __nodeId / $exposeds 原样不动（生产兼容）
编辑态：
  :key="$$eid"  → Vue 差异化重渲染（稳定身份，解决全量重建）
  data-editor-id="$$eid" → 选中/DOM 定位
  onNodeMount($$eid, $el) → 镜像树 + 几何
保存：
  遍历剔除 $$eid → 输出原结构 JSON（__nodeId/$exposeds 不变）→ 生产可直读
```

**收益**：
- `__nodeId` 重复不再影响编辑器（用 `$$eid`）；
- `$exposeds.get('旧id')` 引用零破坏（`__nodeId` 不变）；
- 生产读到的 JSON 与原结构一致。

---

## 三、差异化重渲染如何「可控」（解决核心痛点）

1. **稳定身份**：`:key="$$eid"`（编辑态）→ Vue 不再整树重建；
2. **响应式定点**：属性面板改 `节点X.文字` → 按 `$$eid` 索引找到 `nodeRef` → `nodeRef.__nodeOptions.content = 新值`（AssemCore/props 本就 reactive）→ **仅节点 X 重渲染**；
3. **可控验证**：编辑器可观测单节点 patch，不再「改一处闪全屏」。

> 注：生产无需差异化重渲染（生产一次性渲染），故 `:key` 只在编辑态生效，生产保持现状。

## 七、回滚方案

- **P0 回滚**：还原 `assembox-desktop` 4 个文件（缝增强是纯增量，删除即恢复）；生产版本不升级即可。
- **P1/P2 回滚**：编辑器独立包，停用 iframe 模式回退同 DOM 模式即可，不影响任何存量。

## 八、审核结论建议

- **可行性**：✅ 高（缝已存在，只需增强；生产门控零侵入）。
- **成本**：~10.7 工时日，LOC ~834，**0 改动 500+ 模块**。
