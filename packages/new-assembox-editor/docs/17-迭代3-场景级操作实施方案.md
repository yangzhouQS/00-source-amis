## 二、当前架构约束（源码确认）

### 2.1 schema 结构

```typescript
// schema = uiSkeleton = Record<sceneName, { viewsProps: { planeOptions, ... } }>
```

场景的增删 = 对 schema 顶层 key 的增删。

### 2.2 数据流

```
Editor.store.schema (reactive)
  ├─ schemaRef.value（shallowRef，驱动大纲树/场景切换器响应式）
  └─ state.schema（reactive，commit 时替换引用）

Editor.router (EditorRouter)
  └─ sceneMap: Map<sceneName, RouterSceneConfig>（构造时一次性构建，不可变）

Renderer
  ├─ PcRenderer: sceneState reactive + router 实例（mount 时 buildSceneRouter）
  └─ IframeCanvasRenderer: 同上（iframe 内独立 router）
```

### 2.3 关键约束

| 约束                                                        | 影响                                                                            |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------- |
| **EditorRouter.sceneMap 是构造时冻结的**                    | 增删场景后需要重建路由（addRoute / 重建实例）                                   |
| **vue-router 有 addRoute / removeRoute 动态 API**           | 可在运行时增删路由，无需重建实例 ✅                                             |
| **渲染器 router 也是 mount 时 buildSceneRouter 一次性构建** | 新增场景后渲染器 router 缺新路由，需通知渲染器动态加路由或全量 setSchema 重渲染 |
| **clipboard 在 Editor 实例上（不随场景切换丢失）**          | 跨场景粘贴已天然支持，只需确认 paste 在新场景中 findSlotOf 能找到根节点         |
| **store.commit 每次 cloneSchema + 替换 schemaRef**          | 场景增删走 commit → schemaRef 变更 → 大纲树/切换器自动更新                      |

## 三、实施方案（逐层）

### 3.1 ISchemaOps 扩展（schema 层操作）

**文件**：`scenarios/pc-desktop/schema-ops.ts`

新增 3 个场景级方法：

```typescript
/** 列出所有场景名 */
listScenes(schema: any): string[] {
  return schema && typeof schema === "object" ? Object.keys(schema) : [];
}

/** 新增场景（往 schema 顶层加一个 key） */
addScene(schema: any, sceneName: string, sceneData: any): boolean {
  if (!schema || typeof schema !== "object" || schema[sceneName]) {
    return false; // 场景已存在
  }
  schema[sceneName] = sceneData;
  return true;
}

/** 删除场景（从 schema 顶层移除 key） */
removeScene(schema: any, sceneName: string): boolean {
  if (!schema || typeof schema !== "object" || Object.keys(schema).length <= 1) {
    return false; // 至少保留一个场景
  }
  if (!schema[sceneName]) {
    return false;
  }
  delete schema[sceneName];
  return true;
}
```

**接口定义**（`scenario/types.ts` ISchemaOps）加可选方法：

```typescript
listScenes?: (schema: any) => string[];
addScene?: (schema: any, sceneName: string, sceneData: any) => boolean;
removeScene?: (schema: any, sceneName: string) => boolean;
```

### 3.2 EditorRouter 动态路由（路由层）

**文件**：`core/router/editor-router.ts`

EditorRouter 需支持运行时增删场景路由。vue-router 的 `addRoute()` / `removeRoute()` 满足：

```typescript
export class EditorRouter {
  // 新增
  addScene(name: string, config: RouterSceneConfig): void {
    if (this.sceneMap.has(name)) return;
    this.sceneMap.set(name, config);
    this.routerConfig[name] = config;
    // 动态注册 vue-router 路由
    this.instance.addRoute({
      path: config.path,
      name,
      component: { render: () => h("div") },
      meta: config.meta ?? {},
    });
  }

  // 新增
  removeScene(name: string): void {
    if (!this.sceneMap.has(name)) return;
    this.sceneMap.delete(name);
    delete this.routerConfig[name];
    // 动态移除 vue-router 路由
    this.instance.removeRoute(name);
  }

  getRouterConfig(): RouterConfig {
    return this.routerConfig;
  }
}
```

> **注**：`getRouterConfig()` 已存在（迭代 2），返回当前 routerConfig 引用。增删后该引用同步更新，渲染器 setSchema 时能读到最新路由列表。

### 3.3 Editor 高层 API（编辑器核心）

**文件**：`core/editor.ts`

新增 `addScene()` / `removeScene()`。

**关键决策**：场景增删**不走 commit 历史**，直接修改 schema 并清空历史（`past = []` / `future = []`）。理由：场景是结构级变更，跨场景撤销易导致路由与 schema 不一致，直接清空历史从头开始更安全。

需先在 `core/store.ts` 加 `clearHistory()` 方法：

```typescript
// store.ts 新增
clearHistory(): void {
  this.past = [];
  this.future = [];
}
```

```typescript
// editor.ts 新增

/** 新增场景（页面） */
addScene(sceneName: string, path?: string): void {
  // 1. 校验场景名合法且不重复
  if (!sceneName || this.getScenes().includes(sceneName)) return;

  // 2. 生成空场景数据（复用场景空模板）
  const sceneData = this.profile.emptySchema()[sceneName]
    ?? { viewsProps: { planeOptions: { ...createPcEmptySchema(sceneName)[sceneName].viewsProps.planeOptions } } };

  // 3. 直接修改 schema + 清空历史（不走 commit）
  this.schemaOps.addScene?.(this.store.schema, sceneName, sceneData);
  this.store.schemaRef.value = this.store.schema;
  this.store.clearHistory();

  // 4. EditorRouter 动态加路由
  const routeConfig: RouterSceneConfig = {
    name: sceneName,
    path: path ?? `/${sceneName}`,
    meta: { title: sceneName },
  };
  this.router.addScene(sceneName, routeConfig);

  // 5. 同步渲染器（setSchema 让渲染器读到最新 schema + routerConfig）
  this.syncRenderer();

  // 6. 自动切换到新场景
  this.setScene(sceneName);
}

/** 删除场景（页面） */
removeScene(sceneName: string): void {
  // 1. 校验：不能删除最后一个场景
  const scenes = this.getScenes();
  if (scenes.length <= 1 || !scenes.includes(sceneName)) return;

  // 2. 如果删的是当前场景，先切换到其他场景
  if (this.activeScene === sceneName) {
    const fallback = scenes.find(s => s !== sceneName)!;
    this.store.setActiveScene(fallback);
    this.renderer?.setScene?.(fallback);
  }

  // 3. 直接删除 + 清空历史
  this.schemaOps.removeScene?.(this.store.schema, sceneName);
  this.store.schemaRef.value = this.store.schema;
  this.store.clearHistory();

  // 4. EditorRouter 动态移除路由
  this.router.removeScene(sceneName);

  // 5. 同步渲染器
  this.syncRenderer();
}
```

### 3.4 跨场景复制粘贴（clipboard 层）

**现状分析**：

- `Editor.clipboard` 是实例级属性，不随场景切换丢失 ✅
- `paste(nodeId)` 用 `findSlotOf(nodeId)` 定位插入位置
- 切换场景后 activeId 被清空，若用户直接粘贴（无选中节点），需要 fallback 到当前场景根节点

**改动**（`core/editor.ts`）：

```typescript
/** 粘贴剪贴板节点 */
paste(nodeId?: string): void {
  if (!this.clipboard) return;

  // 有选中节点：粘贴到该节点之后（现有逻辑）
  if (nodeId) {
    const loc = this.schemaOps.findSlotOf?.(this.store.schema, nodeId);
    if (loc) {
      const cloned = this.schemaOps.cloneNode(this.clipboard);
      this.regenerateNodeIds(cloned);
      this.insert(loc.parentId, loc.slotKey, cloned, loc.index + 1);
      this.select(this.schemaOps.getNodeId(cloned));
      return;
    }
  }

  // 无选中节点（场景切换后）：粘贴到当前场景根节点的 defaultSlot
  const rootNode = this.schemaOps.getNodeById(
    this.store.schema,
    this.getCurrentSceneRootId(),
  );
  if (rootNode) {
    const cloned = this.schemaOps.cloneNode(this.clipboard);
    this.regenerateNodeIds(cloned);
    this.insert(this.getCurrentSceneRootId(), "defaultSlot", cloned);
    this.select(this.schemaOps.getNodeId(cloned));
  }
}

/** 获取当前场景的根节点 ID */
private getCurrentSceneRootId(): string {
  const scene = this.store.schema?.[this.activeScene];
  const root = scene?.viewsProps?.planeOptions;
  return root ? this.schemaOps.getNodeId(root) : "";
}
```

**改动量**：约 15 行（paste 方法增强 + 新增 getCurrentSceneRootId）

### 3.6 渲染器路由同步（渲染层）

**现状**：`syncRenderer()` 调用 `renderer.setSchema(store.schema)`。setSchema 会全量同步 schema，但渲染器的 router 实例是 mount 时一次性构建的，新增场景后 router 缺少新路由。

**方案**：在 `setSchema` 时检查 sceneKeys 变化，用 vue-router 的 `addRoute` / `removeRoute` 动态同步。

**PcRenderer 改动**：

```typescript
setSchema(schema: any): void {
  // ... 现有 key 级同步逻辑 ...

  // 新增：动态同步路由（增删场景后 router 需加/删路由）
  this.syncRouterRoutes();
}

private syncRouterRoutes(): void {
  if (!this.router) return;
  const sceneKeys = Object.keys(this.schema || {});
  // 当前 router 已有的路由名
  const existing = new Set(this.router.getRoutes().map((r: any) => r.name).filter(Boolean));
  // 补缺失路由
  for (const name of sceneKeys) {
    if (!existing.has(name)) {
      const cfg = this.runtimeConfig.routerConfig[name];
      this.router.addRoute({
        path: cfg?.path ?? `/${name}`,
        name,
        component: { render: () => h("div") },
        meta: cfg?.meta ?? {},
      });
    }
  }
}
```

**IframeCanvasRenderer 改动**：同理，在 `setSchema` 后调用 `syncRouterRoutes`。但 iframe 的 router 用 `window.VueRouter` 全局构建，`addRoute` API 同样可用。

**改动量**：约 20 行/渲染器

## 五、数据流（新增页面为例）

```
用户点"新建页面"
  → ElMessageBox.prompt 输入名称
  → Editor.addScene("pageNew", "/page-new")
    → schemaOps.addScene(schema, "pageNew", emptyScene)（直接修改 schema 顶层）
    → store.schemaRef.value = schema（触发响应式更新）
    → store.clearHistory()（清空历史，从头累积）
    → EditorRouter.addScene("pageNew", {path:"/page-new"})
      → vue-router addRoute（编辑器侧路由）
    → syncRenderer()
      → renderer.setSchema(最新 schema)
        → PcRenderer.syncRouterRoutes（渲染器侧 router addRoute）
        → IframeCanvasRenderer 同步
    → setScene("pageNew")（自动切换到新页面）
      → store.setActiveScene("pageNew")
      → renderer.setScene("pageNew") → 画布渲染新场景空页面
      → EditorRouter.pushScene("pageNew")

大纲树响应式更新（schemaRef 变化）→ 自动显示新场景分组
场景切换器响应式更新 → 下拉出现新场景
```

## 六、边界与约束

| 场景                    | 处理                                                                                                                                       |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 场景名重复              | `addScene` 返回 false，不操作                                                                                                              |
| 删除最后一个场景        | `removeScene` 拒绝（至少保留一个）                                                                                                         |
| 删除当前激活场景        | 先切换到 fallback 场景再删                                                                                                                 |
| 场景名含非法字符        | UI 层 ElMessageBox.prompt 正则校验                                                                                                         |
| routerConfig 无对应场景 | addScene 用默认 path `/{sceneName}`                                                                                                        |
| **撤销/重做**           | **场景增删后直接清空历史**（`clearHistory`），不支持跨场景 undo。场景内节点操作的 undo/redo 不受影响（历史在场景增删时清零，之后从头累积） |
| 空场景数据              | 复用 `createPcEmptySchema(sceneName)` 的内层结构                                                                                           |
