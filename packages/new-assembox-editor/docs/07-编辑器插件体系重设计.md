# 编辑器插件体系重设计（Spec）

> 状态：设计已确认，待实现
> 形态：方案 A —— `definePlugin()` 工厂函数（对象式）+ 声明式优先
> 配套：`04-lowcode插件设计借鉴分析.md`、`06-amis插件系统设计借鉴分析.md`
> 范围：new-assembox-editor 插件契约、PluginManager、PluginContext、内置插件迁移

---

## 一、背景与目标

### 1.1 现状
当前插件体系（`plugin-types.ts` / `plugin-manager.ts` / `builtin-plugins.tsx` / `register.ts`）已具备：
- 声明式 `contributes`（components/setters/actions/assets/skeleton）
- 广播收集（`buildPanels/buildToolbars/buildContextMenu`）
- EventBus 事件名→方法名 `camelize` 映射（beforeInsert/afterInsert...）
- `scene` 场景 + `priority` 覆盖 + 全局表/本地表 + `init/destroy` 生命周期

### 1.2 痛点（重新设计的驱动力）
1. **多实例污染**：`globalRegistry` 模块级全局表，多个 Editor 实例共享 → 互相污染。
2. **贡献路径不统一**：`coreRegistryPlugin` 用 `init` 手动注册 setter，`componentsPanePlugin` 用 `contributes.skeleton`——两套路径并存，边界模糊。
3. **资源回收隐患**：`destroy?` 与事件订阅分离，无统一 unscribe/dispose 机制。
4. **无插件配置**：缺 `options`（lowcode `preferenceDeclaration` / amis `config.plugins=[Class, options]`）。
5. **无依赖声明**：缺 `dep`，插件间协作靠隐式顺序。
6. **contributes 散落在 editor**：`editor.start()` 手动遍历 contributes 注册，未内聚到 PluginManager。

### 1.3 目标
**简单、高效、易用**的插件体系：统一贡献路径、根治多实例污染与资源泄漏、支持 options/dep 扩展，便于编辑器后续迭代开发。

## 二、设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 插件形态 | `definePlugin()` 工厂（对象式，Vue3 defineComponent 习惯） | 简单轻量，纯数据+可选钩子 |
| 贡献模型 | 声明式 `contributes` 优先 + `setup` 动态副作用 | 静态零样板，动态够灵活 |
| 注册作用域 | 实例级（废弃模块级全局表为主路径） | 根治多实例污染 |
| 生命周期 | `setup` 返回 `dispose` 统一回收 | 根治资源泄漏 |
| 依赖 | `dep` 声明 + 拓扑排序 | 支持插件协作 |
| 配置 | `register(plugin, options)` / `setup(ctx, options)` | 插件可配置化 |
| 钩子 | 保留 `camelize` 方法名映射 + `return false` 阻止 | 已验证可用，零样板 |

## 三、插件契约

### 3.1 definePlugin 与 EditorPluginObject

```ts
/** 插件对象（工厂产物） */
export interface EditorPluginObject<TOptions = any> {
  /** 唯一标识（同 id 按 priority 覆盖） */
  readonly id: string;
  /** 显示名 */
  name?: string;
  /** 优先级（默认 0，大者胜出） */
  priority?: number;
  /** 适用场景（默认 'global'；'global' 在所有场景生效） */
  scene?: string | string[];
  /** 依赖的插件 id（激活时拓扑排序，被依赖者先 setup） */
  dep?: string[];

  /** ① 静态声明贡献 —— 框架在 activate 时自动注册，零样板 */
  contributes?: PluginContributes;

  /** ② 动态副作用 —— 需 ctx/options/事件订阅/条件注册时用，返回 dispose 自动回收 */
  setup?(
    ctx: PluginContext,
    options?: TOptions
  ): void | Promise<void> | (() => void | Promise<void>);

  /** ③ 生命周期事件钩子 —— 约定方法名映射（camelize），return false 阻止操作 */
  beforeInsert?(context: any): void | false | Promise<void | false>;
  afterInsert?(context: any): void;
  beforeUpdate?(context: any): void | false | Promise<void | false>;
  afterUpdate?(context: any): void;
  beforeDelete?(context: any): void | false | Promise<void | false>;
  afterDelete?(context: any): void;
  beforeMove?(context: any): void | false | Promise<void | false>;
  afterMove?(context: any): void;
}

/** 工厂函数：类型守卫 + 默认值注入（保留扩展点） */
export function definePlugin<TOptions = any>(
  def: EditorPluginObject<TOptions>
): EditorPluginObject<TOptions>;
```

### 3.2 三入口贡献边界（核心心智模型）

| 入口 | 何时用 | 谁处理 | 示例 |
|---|---|---|---|
| `contributes` | 静态、可序列化、无条件 | 框架在 activate 自动注册到 registry/skeleton | 注册组件/setter/面板/动作 |
| `setup` | 动态、需 options、需订阅事件、需条件判断 | 插件自己；返回 dispose 回收 | 订阅 afterInsert 做埋点、条件性注册 |
| `before*/after*` | 拦截 schema 操作 | EventBus 方法名映射 | beforeDelete 二次确认、afterMove 同步外部状态 |

**关键约束**：静态 setter 走 `contributes.setters`（框架自动注册），不再在 `setup` 里手动注册——彻底统一贡献路径。

### 3.3 PluginContributes（沿用现有结构）

```ts
export interface PluginContributes {
  components?: ComponentMeta[];
  setters?: SetterMeta[];
  actions?: ActionMeta[];
  assets?: AssetMeta[];
  skeleton?: SkeletonContribution[];
}
```

## 四、PluginManager 与生命周期

### 4.1 API

```ts
class PluginManager {
  /** 实例级注册（携带 options）；废弃模块级全局表为主路径 */
  register<T>(plugin: EditorPluginObject<T>, options?: T): void;
  /** 取消注册（仅 activate 前有效） */
  unregister(id: string): void;
  /** 按 id 查找（供 setup 内跨插件协作） */
  getPlugin<T = any>(
    id: string
  ): {plugin: EditorPluginObject<T>; options?: T} | undefined;

  /** 激活：收集 → 去重 → scene 过滤 → dep 排序 → setup → contributes 应用 → 绑钩子 */
  async activate(ctx: PluginContext, scene: string): Promise<void>;

  /** 广播收集（保留，含 try-catch） */
  buildPanels(node: any, panels: PanelItem[]): void;
  buildToolbars(node: any, toolbars: ToolbarItem[]): void;
  buildContextMenu(node: any, menus: ContextMenuItem[]): void;

  getPlugins(): EditorPluginObject[];

  /** 销毁：逆序 dispose + 解绑事件 + skeleton/registry 反注册 */
  destroy(): void;
}
```

### 4.2 activate 流程

```
1. 收集：实例表(register) + 内置默认表(createEditor 注入)
2. 去重：同 id 按 priority 取胜者（携带其 options）
3. scene 过滤：plugin.scene 含 'global' 或当前 scene 者保留
4. dep 拓扑排序：
   - 构建依赖图，Kahn 算法拓扑排序
   - 被依赖插件先 setup
   - 检测循环依赖 → console.warn + 降级为 priority 兜底排序
5. 依次 setup(ctx, options)：
   - try-catch 单个失败不阻断
   - 收集返回的 dispose 函数到 disposes[]
6. contributes 自动应用：
   - 遍历激活插件 contributes
   - skeleton → skeleton.add；components → componentRegistry；setters → setterRegistry；actions → actionRegistry；assets → assetRegistry
   - 每类 try-catch
7. bindEventHooks：
   - camelize 映射 before-insert → beforeInsert 等
   - 仅当某插件存在该方法时绑定
   - return false → preventDefault+stopPropagation；Promise → event.pending
```

### 4.3 destroy 流程

```
1. 逆序调用 disposes[]（setup 返回的清理函数）
2. 解绑所有 EventBus 监听（unsubscribers）
3. skeleton/registry 反注册（contributes 注册的面板/组件/setter/动作），彻底回收
4. 清空 instances/disposes/ctx
```

## 五、PluginContext

```ts
export interface PluginContext {
  editor: Editor;
  store: EditorStore;
  bus: EventBus;            // on/off/trigger（setup 内订阅事件）
  skeleton: Skeleton;       // add/remove（动态加面板，setup 内用）
  componentRegistry: ComponentRegistry;
  setterRegistry: SetterRegistry;
  assetRegistry: AssetRegistry;
  actionRegistry: ActionRegistry;
  di: DIContainer;
  /** 跨插件协作（配合 dep） */
  getPlugin<T = any>(id: string): {plugin: EditorPluginObject<T>; options?: T} | undefined;
}
```

**使用约束**：`contributes` 声明的静态贡献由框架在 activate 后自动处理；`setup` 内仅做"动态/条件/事件订阅"，通过 ctx.bus/ctx.skeleton/ctx.registry 操作。

## 六、迁移策略

破坏性但项目内部可控（外部无消费者）。

| 现状 | 新设计 | 改动 |
|---|---|---|
| `builtin-plugins.tsx` 7 插件（对象字面量 `EditorPlugin`） | `definePlugin({...})` 包装，`contributes` 不变 | 小 |
| `coreRegistryPlugin.init` 手动 `registerBuiltinSetters/registerBuiltinActions` | `contributes.setters/actions` 声明，框架自动注册；或保留 `setup`（动态场景） | 小（统一路径） |
| `register.ts` 全局自注册（`registerBuiltinPlugins`） | 移除；`createEditor({ plugins: builtinPlugins })` 默认注入 + `disableBuiltin?: boolean` 开关 | 中 |
| `editor.start()` 手动遍历 contributes 注册 | 收敛进 `PluginManager.activate`（contributes 自动应用） | 中 |
| `EditorPlugin` 接口 | 重命名 `EditorPluginObject` + `definePlugin` 工厂 | 全局类型替换 |
| `PluginManager` 构造 `extraPlugins` | `register(plugin, options)` 实例级 | API 调整 |
| `globalRegistry` 模块级 + `registerPlugin/unregisterPlugin` 全局函数 | 删除；统一为 PluginManager 实例级 `register/unregister` | 删 |

### 6.1 迁移后内置插件示例

```ts
// 组件库插件（contributes 声明，几乎不变）
export const componentsPanePlugin = definePlugin({
  id: 'builtin-components-pane',
  name: '组件库',
  scene: 'global',
  contributes: {
    skeleton: [{ area: 'leftArea', type: 'PanelDock', name: 'componentsPaneDock', ... }]
  }
});

// 核心注册插件（init → contributes.setters，统一路径）
export const coreRegistryPlugin = definePlugin({
  id: 'builtin-core-registry',
  name: '核心注册',
  scene: 'global',
  contributes: {
    setters: builtinSetterMetas,
    actions: builtinActionMetas
  }
});
```

### 6.2 createEditor 接口调整

## 七、错误处理

- `setup` / `buildPanels` / `buildToolbars` / `buildContextMenu` / `before*/after*` 钩子 / contributes 注册：全部 try-catch，单个插件失败仅 `console.error('[PluginManager] 插件 "{id}" {阶段} 出错:', err)`，不阻断其他插件。
- `setup` 抛错时仍记录该插件为已激活（不阻断后续插件 setup），但不收集其 dispose。
- dep 循环依赖：warn 并降级为 priority 排序（保证不卡死）。

## 八、测试

### 8.1 单元测试（vitest，纯函数）
- `definePlugin`：透传、默认值（priority=0、scene='global'）。
- `PluginManager.activate`：
  - priority 覆盖（同 id 取大者，携带 options）
  - scene 过滤（global 全场景、指定场景）
  - dep 拓扑排序（B 依赖 A → A 先 setup；循环依赖降级）
  - options 透传 setup
  - dispose 回收顺序（逆序）与异常隔离
  - contributes 自动注册（skeleton/components/setters 到对应 registry）
- `bindEventHooks`：camelize 映射、return false 阻止、Promise pending。

### 8.2 回归测试（现有 e2e smoke）
- 迁移后画布（iframe/inline）、组件面板、设置面板、大纲、源码、历史面板仍正常渲染（2 passed 保持）。

## 九、与借鉴文档的对应

| 本设计特性 | 借鉴来源 | 落地点 |
|---|---|---|
| `definePlugin` 工厂（对象式） | Vue3 defineComponent 习惯 | 契约 |
| `contributes` 静态声明 + `setup` 动态 | lowcode factory + ctx / amis panelBody 声明 | 三入口边界 |
| 实例级 register（废弃全局表） | lowcode 实例级 PluginManager | PluginManager |
| `dep` 拓扑排序 | lowcode plugin.dep / amis dep | activate 流程 |
| `options` 配置 | lowcode preferenceDeclaration / amis [Class, options] | register/setup |
| `setup` 返回 dispose | React useEffect / Vue onScopeDispose | 生命周期 |
| `camelize` 方法名映射 | amis trigger camelize | bindEventHooks（保留） |
| 广播收集 buildPanels/Toolbars | amis collectPanels/buildToolbars | PluginManager（保留） |
| priority 覆盖 | lowcode/amis priority | activate 去重（保留） |

## 十、范围与非目标（YAGNI）

**本设计包含**：插件契约重定义、PluginManager 实例化、contributes 自动应用、dep/options/dispose、内置插件迁移。

**明确不做（留待后续）**：
- 动态加载/远程插件（contributes.skeleton.content 仍持有组件引用）—— 需独立的资产包工程化（对应 05 文档 P2-1）。
- 插件市场/版本管理。
- preferenceDeclaration 完整 schema 校验（仅做 options 透传）。
- 跨编辑器插件共享（实例级隔离，不提供共享层）。
