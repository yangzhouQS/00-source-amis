## 一、P0 交付链路（不补则产物无法上线）

| # | 缺失 | 说明 | 工作量 |
|---|---|---|---|
| 1 | **schema 保存到服务端** | 目前仅 sessionStorage 草稿。需要对齐宿主保存接口（旧版 useProject 的 saveSchema 链路：模块配置 → 服务端持久化 → 版本记录） | 2-3d |
| 2 | **schema 加载校验 + 迁移** | 拉取存量 JSON 后无结构校验（__nodeId/renderType 合法性、槽位形态合法性——错误结构直接导致渲染崩溃，如数组化单节点槽）；需要 loadSchema 前置 validate + 修复管道（兼容 docs/20 审计前的坏数据） | 2d |
| 3 | **产线渲染接入** | 编辑器产出 schema → 宿主站点（vue-mb-output-design-website 等）以**生产模式**渲染（非编辑器 iframe）。需要：生产依赖清单收敛（CDN 稳定版锁定）、pinia/portalStore 桥接文档化、AssemEditor IIFE 与宿主 WebFramework 生命周期对齐文档 | 2d |
| 4 | **预览发布链路** | 独立预览页（无编辑器壳、真实数据、路由可达），供业务验收 | 1-2d |

## 二、P0 页面/文档管理（多文档是硬需求）

| # | 缺失 | 说明 | 工作量 |
|---|---|---|---|
| 5 | **Dialog/Drawer/Tab 文档编辑** | schema 里已有独立文档树（dialogOptions/drawerOptions/tabOptions），编辑器**无法新建/打开/编辑**这些文档——业务里弹窗表单是刚需。需要：文档树管理 UI（新建/重命名/删除）+ DesignerHost 文档切换 + 渲染器按文档挂载 | 3-4d |
| 6 | **多路由页面管理** | docs/16 已设计（多路由页面切换），未实施。单模块多页面（列表页/编辑页）是真实模块常态 | 3d（依赖 #5） |
