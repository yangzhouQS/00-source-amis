## 二、五个接口定义

### 2.1 ISchemaOps

```typescript
interface ISchemaOps {
  // ── 标识 ──
  getNodeId(node: any): string;
  setNodeId(node: any, id: string): void;
  genNodeId(type: string): string;
  getNodeLabel(node: any): string;

  // ── 遍历 ──
  getNodeById(schema: any, id: string): any | undefined;
  getParentById(schema: any, id: string): any | undefined;
  walk(schema: any, visitor: (node: any, parent: any | null, slotKey: string) => void): void;
  getSlotChildren(parentNode: any, slotKey: string): any[];
  getSlots(node: any): { key: string; label: string }[];

  // ── 增删改（原地修改 schema，返回被操作的节点）──
  insertNode(schema: any, parentId: string, slotKey: string, node: any, index?: number): any | undefined;
  removeNode(schema: any, nodeId: string): any | undefined;
  moveNode(schema: any, nodeId: string, toParentId: string, slotKey: string, index?: number): boolean;
  updateNode(schema: any, nodeId: string, patch: any): any | undefined;
  cloneNode(node: any): any;
  cloneSchema(schema: any): any;

  // ── 节点工厂 ──
  createNode(renderType: string, nodeName: string, overrides?: any): any;
  emptySchema(): any;
}
```

> **类型策略**：接口保持 `any`（格式无关），PC 实现类 `PcSchemaOps` 内部用 `IBaseNode` 泛型约束，编译期安全。

### 2.2 IRenderer（设计态渲染器）

> 对应 lowcode-engine 的 simulator-renderer：在 assembox-desktop-next（生产渲染器）之上增加编辑器专属的 DOM 标记、槽位标记、事件拦截、reactive schema 桥接。

```typescript
interface IRenderer {
  // ── 生命周期 ──
  /**
   * 初始化并挂载。
   *
   * ⚠️ P0 关键：schema 必须是 Store 管理的 reactive 对象（同一个引用），
   * 这样 ISchemaOps 的原地修改能通过 Vue reactivity 自动传播到渲染器，
   * 无需手动 setSchema（结构变更靠 reactive 数组操作自动 diff）。
   */
  mount(container: HTMLElement, schema: any, options?: RendererMountOptions): Promise<void>;

  /**
   * 全量替换 schema（仅用于 loadSchema/importJSON 等整树替换场景）。
   * 日常增删改走 ISchemaOps 原地修改 + reactive 传播，不调此方法。
   */
  setSchema(schema: any): void;

  /**
   * 局部属性更新（可选优化：走 NodeRegistry.patchProps 而非 reactive）。
   * 如果 schema 是 reactive 的，此方法可空实现（reactivity 自动处理）。
   */
  updateNode?(nodeId: string, patch: any): void;

  /** 结构变更后的通知（可选：用于手动触发重渲染的非 reactive 渲染器） */
  onStructureChange?(): void;

  /** 设置拖拽态（禁止画布交互 + 改光标） */
  setDraggingState(active: boolean): void;

  /**
   * 设置设计/预览模式。
   *
   * 'design'：拦截事件（不执行 __nodeEvent handler）、打 DOM 标记、显示 BemTools
   * 'preview'：放行事件、不打标记、隐藏 BemTools
   *
   * 依赖 assembox-desktop-next 的 useEditor 增强：
   *   window.assemBoxDesignMode = 'design' | 'preview'
   *   useNodeEvents 检查此变量决定是否注册事件
   *   useEditor 检查此变量决定是否打 data-editor-id
   */
  setDesignMode(mode: 'design' | 'preview'): void;

  /** 销毁 */
  dispose(): void;

  // ── DOM 标记查询 ──
  /** 通过 data-editor-id 获取节点根元素 */
  getNodeElement(nodeId: string): HTMLElement | null;
  /** 获取节点几何（供 BemTools 高亮框） */
  getRect(nodeId: string): DOMRect | null;
  /** 从 DOM 元素反查节点 id */
  nodeIdFromElement(el: HTMLElement | null): string | null;

  // ── 槽位查询 ──
  /** 获取某节点各槽位的 DOM 区域（拖拽时识别目标槽位） */
  getSlotMarkers(nodeId: string): SlotMarker[] | null;
  /** 从 DOM 元素解析所属节点 + 槽位（供选区 + 拖拽落点解析） */
  resolveFromElement(el: HTMLElement | null): { nodeId: string; slotKey: string } | null;

  // ── 事件回调 ──
  onReady?(cb: () => void): void;
  onClick?(cb: (nodeId: string | null, e: MouseEvent) => void): void;
  onHover?(cb: (nodeId: string | null) => void): void;
}

interface SlotMarker {
  slotKey: string;
  el: HTMLElement;
  rect: DOMRect;
}

interface RendererMountOptions {
  /** 编辑器模式 */
  isEditor?: boolean;
}
```

## 三、P0 问题解决方案

### 3.1 Reactive Schema 数据流（P0-1）

**问题**：AssemCore 构造时深拷贝 uiSkeleton，编辑器改 Store.schema 后 AssemCore 内部副本不更新。

**解决**：IRenderer 的 PC 实现接管 schema 管理权——不把 schema 交给 AssemCore 深拷贝，而是：

```
Store.schema (reactive)
    │
    ├─ ISchemaOps 原地修改（insert/remove/move/update）
    │
    └─ IRenderer PC 实现 持有同一 reactive 引用
         │
         ├─ AssemPlugin.install() 时传入 reactive schema
         │  → AssemCore 不深拷贝（或 IRenderer 层做 reactive 包装后传入）
         │
         └─ Vue reactivity 自动传播：
            属性变更 → useNodeOptions computed 重算 → 组件局部重渲染
            结构变更 → defaultSlot 数组操作 → Vue diff → 子树局部重建
```

**需要验证**：AssemCore 构造函数是否深拷贝 uiSkeleton。如果是，IRenderer 层需要：
- 方案 A：mount 后用 `$assemCore.uiSkeletonOptions = schema` 替换引用（如果 AssemCore 支持）
- 方案 B：修改 AssemCore 构造，不拷贝（assembox-core-next 配合改动）
- 方案 C：IRenderer 层包装一层 reactive proxy，拦截变更同步到 AssemCore 内部

### 3.2 结构变更策略（P0-2）

**问题**：无增量结构更新 API，全量 re-mount 会丢失组件状态。

**解决**：利用 Vue reactivity 的数组 diff 能力。

```
插入节点：
  ISchemaOps.insertNode(schema, parentId, 'defaultSlot', node, index)
  → parent.__nodeOptions.defaultSlot.splice(index, 0, node)  // reactive 数组操作
  → Vue 自动 diff AssemNodeRenderer 的 v-for
  → 只重建受影响位置的子组件，其余组件不动（保留状态）

删除节点：
  → array.splice(index, 1)
  → Vue 自动卸载对应子组件

移动节点：
  → 从原数组 splice 移除 + 在目标数组 splice 插入
  → Vue diff 自动处理
```

**前提条件**：schema 必须是 reactive 的（P0-1 解决后），且组件模板用 `:key="node.__nodeId"` 做 v-for（assembox-desktop-next 的 AssemNodeRenderer 需确认是否有 key）。

### 3.3 设计态事件拦截（P0-3）

**问题**：设计态点击 Button → 触发 onClick → 调用生产 API。

**解决**：增加 `window.assemBoxDesignMode` 全局变量。

| assembox-desktop-next 文件 | 改动 | 门控 |
|---|---|---|
| `useNodeEvents.ts` | 注册事件前检查 `window.assemBoxDesignMode !== 'design'`，设计态跳过注册 | 新增检查 |
| `useEditor.ts` | 检查 `window.assemBoxDesignMode` 决定是否打 `data-editor-id` | 新增检查 |

```typescript
// useNodeEvents.ts 增量
if (isEditorEnv() && window.assemBoxDesignMode === 'design') {
  // 设计态：不注册事件 handler
  return;
}
```

编辑器 IRenderer 实现：
```typescript
setDesignMode(mode) {
  window.assemBoxDesignMode = mode;
  // BemTools 监听 store.designMode 控制显隐（已有）
}
```

**双保险**：编辑器仍在 iframe/host doc 上挂 capture-phase click 拦截器（已有），防止遗漏的非 click 事件。

## 四、P1 问题解决方案

### 4.1 Dragon/CanvasSensor 与 IRenderer/INestingRules 集成

**问题**：CanvasSensor 拖拽时需要调用 IRenderer.getSlotMarkers() + INestingRules.canNest()，但当前接口未注入。

**解决**：CanvasSensor 构造时注入 editor（从中获取 profile 引用）：

```typescript
class CanvasSensor implements DragSensor {
  constructor(
    opts: CanvasSensorOptions,
    private editor: Editor  // ← 注入 editor，获取 renderer/nestingRules/schemaOps
  ) {}

  locate(target, x, y): DropLocation | null {
    // 1. 从 DOM 元素解析节点 + 槽位
    const resolved = this.editor.renderer.resolveFromElement(target);
    if (!resolved) return null;

    // 2. 嵌套校验
    const childType = this.editor.dragon.dragObject?.data?.renderType;
    if (childType && !this.editor.nesting.canNest(
      resolved.parentRenderType, resolved.slotKey, childType
    )) {
      return null;  // 不允许，不显示指示线
    }

    // 3. 计算插入索引（基于槽位子元素几何）
    const markers = this.editor.renderer.getSlotMarkers(resolved.nodeId);
    // ... 按 Y 坐标排序计算 index ...

    return { parentId: resolved.nodeId, slotKey: resolved.slotKey, index };
  }
}
```

### 4.2 预览模式渲染行为

| 模式 | `assemBoxDesignMode` | `data-editor-id` 标记 | 事件 handler 注册 | BemTools |
|---|---|---|---|---|
| design | `'design'` | ✅ 打标记 | ❌ 不注册 | ✅ 显示 |
| preview | `'preview'` | ❌ 不打 | ✅ 正常注册 | ❌ 隐藏 |

切换时编辑器调 `IRenderer.setDesignMode(mode)` → 设全局变量 → assembox-desktop-next 组件自动响应（需重新渲染生效，可触发 reactive 刷新）。

## 九、关键决策记录

| 决策 | 理由 |
|---|---|
| **IRenderer 是必需封装层** | 生产渲染器缺少 DOM 标记/槽位标记/事件拦截/reactive schema |
| **useEditor 增强方案** | 组件自己知道 DOM 结构，标记最精准；isEditorEnv() 门控保证生产零影响 |
| **reactive schema 桥接** | 不用全量 re-mount，利用 Vue reactivity 的数组 diff 做增量结构更新，保留组件状态 |
| **assemBoxDesignMode 事件门控** | 设计态不注册事件 handler，从源头拦截而非 capture-phase 补丁 |
| **ScenarioProfile 含生命周期钩子** | 不同场景贡献专属 setter/面板/快捷键 |
| **CanvasSensor 注入 editor** | 拖拽时通过 IRenderer + INestingRules 做槽位识别和校验 |
| **不保留 amis schema** | 推倒重来 |
| **不引入中间格式** | 原生操作 IBaseNode |
| **ComponentCatalogItem 手动维护** | manifest.ts 只有类型，scaffold + props 是编辑器专属；长期目标自动化同步 |
| **第一版同 DOM 模式** | iframe 模式接口预留，实现延后 |
| **第一版 snapshot history** | 先跑通，后续优化为 patch-based |
