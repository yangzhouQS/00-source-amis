## 一、问题定义

### 1.1 现状（已确认的架构事实）

**schema 结构**（`uiSkeleton`）：

```
uiSkeleton
├── orderList    ← 场景（Scene）= 一个页面
│   └── viewsProps
│       ├── planeOptions      ← 页面主树
│       ├── dialogOptions[]   ← 弹窗文档树
│       └── ...
├── orderDetail
└── orderEdit
```

**routerConfig**（与 uiSkeleton 场景 1:1）：

```json
{
  "orderList":   { "name": "orderList",   "path": "/order-table", "meta": { "title": "主模块" } },
  "orderDetail": { "name": "orderDetail", "path": "/order-detail", "meta": { "title": "详情界面" } },
  "orderEdit":   { "name": "orderEdit",   "path": "/order-edit",   "meta": { "title": "编辑界面" } }
}
```

**当前缺陷**（全部已源码确认）：

|  #  | 缺陷                          | 证据                                                                                                                                                      |
| :-: | ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
|  1  | **渲染器硬编码 `scenes[0]`**  | `PcRenderer.mount`（renderer.ts:68-74）、`IframeCanvasRenderer.mount`（iframe-canvas-renderer.ts:122-129）都只取 `Object.values(schema)[0]`               |
|  2  | **编辑器不持有 routerConfig** | `EditorOptions` 只有 `schema`，main.tsx:45 只传 `(schemaJson as any).uiSkeleton`                                                                          |
|  3  | **渲染器 dataSource 为空壳**  | renderer.ts:62 / iframe-canvas-renderer.ts:112 传 `{ api:{config:{}}, requestConfig:{}, ... }` 空对象，真实 dataSource 未下发                             |
|  4  | **vue-router 未安装**         | 编辑器 package.json 无 vue-router 依赖；canvas.html 仅 CDN 加载全局，但**没有任何地方 createRouter/install**；NavigationBar 的 `routers` 配置当前完全失效 |
|  5  | **Store 无场景概念**          | `EditorStore.state` 无 `activeScene`；`loadSchema`/`commit` 只认整棵 schema                                                                               |
|  6  | **大纲树不分场景**            | `buildOutlineFromSchemaOps` 把全部场景节点拼成一棵树                                                                                                      |

### 1.3 旧版实现的关键参考（源码确认）

对照 `node-mp-assem-editor-website`，有四个必须借鉴的模式：

| 参考                                  | 文件                                         | 关键结论                                                                                                                         |
| ------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **AssemConfig.routerConfig 原生支持** | `@cs/assembox-core-next` `assem-config.d.ts` | 新运行时类型**已声明 `routerConfig?: RouterConfig`**（`Record<string, {name, path, meta}>`），但 bundle 内零消费——消费方是宿主   |
| **$globalVars.$router 注入**          | `assem-preview/router/bind-assem-context.ts` | `assemCore.$globalVars.$router = router`——路由实例必须注入 `$globalVars`，场景事件函数才能用 `ctx.$globalVars.$router.push(...)` |
| **动态路由 addRoute**                 | `assem-preview/router/create-route-page.ts`  | 用 `router.addRoute({path, name, meta, component})` 逐条动态注册，完成后 `router.replace({path:"/"})` 跳默认页                   |
| **按场景名取配置渲染**                | `assem-preview/router/render-route-page.tsx` | 页面组件从 `$assemCore.uiSkeletonOptions[pageCode]` 按场景名取 viewsProps 渲染（而非 scenes[0]）                                 |
| **依赖下发**                          | `utils/dependencies-helpers.ts`              | `editor.set(ASSEM_RENDER_DEPENDENCIES_KEY, deps)` 编辑器持有配置，渲染器读取                                                     |

**三个对我原设计的修正点**：

1. **`$globalVars.$router` 注入必须显式设计**——旧版 `bindAssemContext` 的核心动作就是把它挂到 `assemCore.$globalVars`。我原设计只建了 EditorRouter 实例，缺这一步。
2. **路由组件应为"场景渲染代理"**——旧版 `RenderRoutePage` 用 `key=pageCode` + `views` 组件渲染对应场景。我的占位 `h("div")` 方案可行但应显式对齐此模式。
3. **routerConfig 已在运行时类型契约中**——无需自定义 `RouterSceneConfig` 完全兼容运行时类型，直接复用 `AssemConfig["routerConfig"]` 形状。

### 1.2 目标

引入 vue-router 作为路由管理，实现：

1. **设计态**：编辑器内可在多个路由页面（场景）间切换编辑，画布渲染当前激活场景
2. **预览态**：NavigationBar 的 `routers` 真实生效，点击导航在页面间跳转
3. **数据贯通**：routerConfig + dataSource 随 schema 一起下发到渲染器
4. **架构分层**：路由层与编辑器核心解耦，可插拔（不同场景可用不同路由配置）

## 二、总体设计

### 2.1 三层职责划分

```
┌─────────────────────────────────────────────┐
│ Editor（编辑器核心）                          │
│  - 持有 routerConfig / dataSource / schema   │
│  - 创建 EditorRouter（vue-router 实例）      │
│  - 维护 activeScene（响应式，驱动画布切换）   │
└─────────────────────────────────────────────┘
        │ activeScene 变化 → setScene()
        ▼
┌─────────────────────────────────────────────┐
│ IRenderer（渲染器协议）                      │
│  - setSchema(整个 uiSkeleton)               │
│  - setScene(sceneName)   ← 新增             │
│  - 渲染当前激活场景的 viewsProps             │
└─────────────────────────────────────────────┘
        │
        ├── PcRenderer（inline 同 DOM）
        │     └── 内部持有 vue-router，createApp 时 install
        └── IframeCanvasRenderer（iframe 隔离）
              └── 协议新增 setScene / setRouterConfig
                  iframe 内 createApp 时 install router
```

### 2.2 路由的双重角色

vue-router 在编辑器中承担两个角色，需区分：

|     角色     | 模式   | 用途                                                                | 历史                                    |
| :----------: | ------ | ------------------------------------------------------------------- | --------------------------------------- |
| **编辑路由** | 设计态 | 编辑器内部"当前编辑哪个页面"的状态管理（activeScene ↔ router path） | `createMemoryHistory`（不污染地址栏）   |
| **预览路由** | 预览态 | NavigationBar 点击导航、页面真实跳转                                | `createMemoryHistory`（画布 iframe 内） |

**关键决策**：编辑器整体用 `createMemoryHistory`（内存历史），避免编辑器的 URL 被设计操作污染，且天然支持多实例共存。

### 3.2 新增 EditorRouter 类（封装 vue-router）

```typescript
// core/router/editor-router.ts
import { createMemoryHistory, createRouter, type RouteRecordRaw } from "vue-router";
import { h } from "vue";

export class EditorRouter {
  readonly instance: Router;              // vue-router 实例
  private sceneMap: Map<string, RouterSceneConfig>;  // sceneName → config

  constructor(routerConfig: Record<string, RouterSceneConfig> = {}) {
    this.sceneMap = new Map(Object.entries(routerConfig));
    this.instance = createRouter({
      history: createMemoryHistory(),
      routes: this.buildRoutes(),
    });
  }

  /** 构建 vue-router routes（每个场景一条，组件为场景渲染代理） */
  private buildRoutes(): RouteRecordRaw[] {
    return [...this.sceneMap.values()].map(cfg => ({
      path: cfg.path,
      name: cfg.name,
      // 场景渲染代理（对齐旧版 RenderRoutePage 模式）：
      // 实际 viewsProps 由渲染器从 schema[sceneName] 取，路由组件仅作占位
      component: { render: () => h("div") },
      meta: cfg.meta ?? {},
    }));
  }

  getSceneConfig(name: string): RouterSceneConfig | undefined { ... }
  getScenes(): RouterSceneConfig[] { ... }
  getPath(name: string): string | undefined { ... }
  getNameByPath(path: string): string | undefined { ... }
  async pushScene(name: string): Promise<void> {   // 切换到某场景路由
    await this.instance.push({ name });
  }
}
```

> **注**：`EditorRouter.instance` 是**编辑器侧**的路由（memory history，管理"当前编辑哪个页面"）。画布 iframe 内侧的渲染路由由 iframe 渲染器独立构建（见 3.7），两者通过协议同步场景名，不共享实例——与旧版 preview 模块（`createPageRouter` 在 preview.html 独立建路由）一致。

### 3.3 Editor 扩展

```typescript
export class Editor {
  readonly router: EditorRouter;         // 新增
  readonly dataSource: AssemDataSource;  // 新增（透传给渲染器）
  readonly globalVars: Record<string, any>;  // 新增（注入 $globalVars）

  // 新增：当前激活场景
  get activeScene(): string { return this.store.state.activeScene; }
  get activeSceneConfig(): RouterSceneConfig | undefined {
    return this.router.getSceneConfig(this.activeScene);
  }

  /** 切换到指定场景（路由跳转 + 画布渲染 + 清空选区） */
  async setScene(sceneName: string): Promise<void> {
    // 1. 校验场景存在
    if (!this.router.getSceneConfig(sceneName)) return;
    // 2. 触发 BEFORE_SCENE_CHANGE
    const ev = this.bus.trigger(EVENT.BEFORE_SCENE_CHANGE, { from: this.activeScene, to: sceneName });
    if (ev.prevented) return;
    // 3. store 记录 activeScene + 清空选区
    this.store.setActiveScene(sceneName);
    // 4. 渲染器切换
    this.renderer?.setScene?.(sceneName);
    // 5. 路由跳转（memory history）
    await this.router.pushScene(sceneName);
    // 6. 触发 AFTER_SCENE_CHANGE
    this.bus.trigger(EVENT.AFTER_SCENE_CHANGE, { sceneName });
  }
}

/** 全局变量注入（对齐旧版 bindAssemContext） */
// Editor 构造时 / renderer mount 时：
function injectGlobalVars(assemCore: any, vars: Record<string, any>) {
```

### 3.6 PcRenderer 改造（inline 模式）

```typescript
export class PcRenderer implements IRenderer {
  private activeScene: string | null = null;
  private routerConfig: Record<string, RouterSceneConfig> = {};
  private dataSource: any = null;

  /** 扩展 mount options：接收 routerConfig / dataSource */
  async mount(container, schema, options?: RendererMountOptions): Promise<void> {
    // ...
    this.routerConfig = options?.routerConfig ?? {};
    this.dataSource = options?.dataSource;

    // 读取 schema 场景 → 构建 vue-router → install
    const scenes = Object.keys(this.schema);
    this.activeScene = this.activeScene ?? scenes[0] ?? null;
    const router = buildRouterForScene(this.routerConfig, scenes, this.activeScene);

    this.app = createApp({
      render: () => {
        const scene = this.schema[this.activeScene!];
        if (!scene?.viewsProps) return h("div", "空场景");
        return h(AssemViews, { viewsProps: scene.viewsProps });
      },
    });
    this.app.use(router);       // ← install vue-router
    this.app.use(AssemPlugin, { uiSkeleton: schema, dataSource: this.dataSource, ... });
    // ...
  }

  setScene(sceneName: string): void {
    this.activeScene = sceneName;
    // 触发重渲染（activeScene 变化 → render 函数重跑）
    this.app?.mount?.(...);   // 或依赖响应式
  }
}
```

**重要**：`this.activeScene` 需变为响应式（`reactive`），使 render 函数在 `setScene` 后自动重渲染，而非手动 remount。参考 IframeCanvasRenderer 的 `reactive schema` 模式（iframe-canvas-renderer.ts:32）。

```typescript
private activeScene: string | null = null;
private router: any = null;
```

### 3.8 共享工具：根据 routerConfig 构建 vue-router

```typescript
// core/router/build-router.ts
import { createMemoryHistory, createRouter } from "vue-router";

/**
 * 从 routerConfig 构建 vue-router 实例。
 * - 用 memory history（不污染地址栏，支持多实例）
 * - 每条路由映射一个场景（占位组件）
 * - 默认首页重定向到第一个场景
 */
export function buildSceneRouter(
  routerConfig: Record<string, RouterSceneConfig>,
  scenes: string[],
  activeScene: string,
) {
  const routes = [...scenes].map(name => {
    const cfg = routerConfig[name];
    return {
      path: cfg?.path ?? `/${name}`,
      name,
      component: { render: () => h("div") },
      meta: cfg?.meta ?? {},
    };
  });
  if (routes.length && routes[0].path !== "/") {
    routes.push({ path: "/", redirect: routes[0].path });
  }
  return createRouter({ history: createMemoryHistory(), routes });
}
```

### 3.9 画布组件改造：NavigationBar 路由生效

NavigationBar 运行时组件（assembox-desktop-next）通过 `useRouter()` 获取路由实例。安装 router 后：

- **设计态**：`assemBoxDesignMode === "design"` 时，NavigationBar 的 `routers` 展示正常，但点击不应跳转（编辑态点击已被渲染器 mousedown 拦截选中）
- **预览态**：`assemBoxDesignMode === "preview"` 时，点击 NavigationBar 真正 `router.push(path)`，画布切换场景

> ⚠️ 需确认 NavigationBar 组件在 design 模式下是否拦截点击。若无拦截，需在渲染器事件层对预览态放行路由跳转（见 3.10）。

### 3.10 设计/预览态路由行为差异

| 交互                   |        设计态         |             预览态             |
| ---------------------- | :-------------------: | :----------------------------: |
| NavigationBar 展示     |    ✅ 展示所有路由    |        ✅ 展示所有路由         |
| NavigationBar 点击跳转 |  ❌ 拦截（选中组件）  |         ✅ router.push         |
| 编辑器内部场景切换     | ✅ setScene（工具栏） |               —                |
| 画布渲染               |   当前 activeScene    | 当前 activeScene（由路由驱动） |

**实现要点**：渲染器的 click 事件（PcRenderer.bindCanvasEvents / IframeCanvasRenderer.bindCanvasEvents）在 `designMode === "preview"` 时**不拦截**点击（当前已用 `assemBoxDesignMode !== "design"` 判断跳过），因此 NavigationBar 点击在预览态天然可透传给 router。

## 五、风险与决策记录

### 5.1 风险

| 风险                                          | 等级 | 缓解                                                                                                                                                                                                 |
| --------------------------------------------- | :--: | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **iframe 内 $globalVars 注入时机**            |  高  | `$assemCore` 在 `app.mount` 后通过 `app.config.globalProperties.$assemCore` 取得；需在 mount 后、场景事件触发前注入。参考旧版 `bindAssemContext` 在组件 onMounted 时调用                             |
| **NavigationBar 运行时是否 useRouter 需验证** |  中  | 旧版 preview 已证明：install router 后 NavigationBar 可跳转（`createPageRouter` + `bindAssemContext`）。新运行时 NavigationBar 类型仅声明 `routers` prop，具体实现需验证（见迭代 2 步骤 5 前置验证） |
| **iframe 模式 router 双实例**                 |  中  | EditorRouter 只在 host 创建（管理编辑态）；iframe 内侧独立 buildSceneRouter（memory history），两者通过协议同步场景名，不共享实例                                                                    |
| **routerConfig 与运行时类型兼容**             |  低  | 运行时 `AssemConfig.routerConfig` 类型已声明，直接复用形状即可                                                                                                                                       |
| **dataSource 下发后若格式不符**               |  中  | 迭代 2 步骤 6 先验证真实 dataSource 能被 AssemPlugin 消费                                                                                                                                            |
| **activeScene 响应式重渲染成本**              |  低  | 场景切换是低频操作，全量重渲染可接受                                                                                                                                                                 |

### 5.2 决策记录

| 决策                                                    | 理由                                                                                                                                                                  |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **用 `createMemoryHistory` 而非 `createWebHistory`**    | 编辑器地址栏不应被设计操作污染；支持多实例共存；iframe 画布内更适用。旧版 editor/preview 用 `createWebHashHistory` 是因为宿主应用需要 URL 路由，编辑器模块应隔离      |
| **`$globalVars.$router` 必须显式注入**                  | 场景事件函数大量读 `ctx.$globalVars.$router`（order-table-config 已见 `push('/order-edit')`）；运行时类型 `GlobalVars.$router?: unknown` 已声明此扩展点，但需宿主注入 |
| **routerConfig 不入 schema，独立于 EditorOptions 传入** | routerConfig 是"应用路由元数据"，与 uiSkeleton（页面内容）职责分离；schema 保持纯净可编辑。运行时 `AssemConfig.routerConfig` 类型已支持                               |
| **IRenderer.setScene 为可选方法**                       | 兼容未实现场景切换的渲染器（如移动端场景）                                                                                                                            |
| **EditorRouter 与 Editor 解耦**                         | 可单测；不同场景可用不同路由策略                                                                                                                                      |
| **场景切换不进入 history 快照**                         | 切换场景只换 activeScene，不改 schema 内容；历史记录按 schema 维度                                                                                                    |
| **iframe 内侧独立建 router（不共享 EditorRouter）**     | iframe 是独立浏览上下文，无法共享 host 的 Vue/router 实例（与 docs/15 的 iframe reactive 桥结论一致）；通过协议同步场景名                                             |

### 5.3 事件清单

```typescript
EVENT.BEFORE_SCENE_CHANGE  // { from, to }，可 preventDefault
EVENT.AFTER_SCENE_CHANGE   // { sceneName }
```
