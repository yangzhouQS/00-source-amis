## 1. 总览：四层架构

```
┌─────────────────────────────────────────────────────────────┐
│  ① Schema 层（数据形态）                                      │
│     slot-accessors.ts —— 槽位规则表（单一真相源）               │
│     直接槽位 / 间接容器 / 文档数组 三种子节点存储形态              │
├─────────────────────────────────────────────────────────────┤
│  ② 渲染层（运行时执行）                                       │
│     容器模板 <NodeRenderer parent="X" slot-name="y">          │
│     nesting.ts SLOTS 表做嵌套门禁（谁能装谁）                   │
├─────────────────────────────────────────────────────────────┤
│  ③ DOM 标记层（设计态定位基础）                                 │
│     useEditor() → data-editor-id（节点根标记）                  │
│     data-slot-host / data-slot-key（槽位标记，见 §6 缺口）      │
├─────────────────────────────────────────────────────────────┤
│  ④ 拖拽识别层（交互命中）                                      │
│     canvas-sensor.ts findContainerEl 三级命中 + 插入索引计算     │
│     editor.onDrop 嵌套兜底 → insertChildIntoOpts 落地          │
└─────────────────────────────────────────────────────────────┘
```

核心设计原则：

- **schema 与 DOM 双向对应**：schema 里的每个槽位都能在 DOM 找到对应区域（靠标记属性），DOM 上的每个落点都能反查回 schema 槽位（靠命中链）。
- **嵌套规则单表驱动**：渲染校验（nesting.ts `SLOTS`）与拖拽校验（`PcNestingRules.canNest` 包装同一张表）同源，不会出现"拖得进去但渲染不出来"。
- **引用稳定**：渲染链路刻意不克隆节点（详见 §3.3），避免响应式循环。

## 2. Schema 层：槽位存储模型

**文件：`src/scenarios/pc-desktop/slot-accessors.ts`**（364 行，schema-ops 与 renderer 共享的单一真相源）

### 2.1 三种存储形态

子节点全部挂在父节点 `__nodeOptions` 上，分三种形态：

#### 形态 A：直接槽位（DIRECT_SLOTS，:28-36）

```ts
__nodeOptions[field] = node | node[]     // 单节点或节点数组
```

| field | slotKey | label | 典型宿主 |
|---|---|---|---|
| `defaultSlot` | defaultSlot | 内容区 | Panel/Box/Form/ListItem… |
| `toolSlot` | toolSlot | 工具栏 | Panel、Toolbar |
| `filterSlot` | filterSlot | 筛选项 | Toolbar |
| `headerSlot` | headerSlot | 头部 | Dialog/Drawer |
| `bottomSlot` | bottomSlot | 底部 | 表格分页下方 |
| `labelSlot` | labelSlot | 标签 | TabPanel 页签 |
| `rightSlot` | rightSlot | 右侧 | FlexLine |

#### 形态 B：间接容器（INDIRECT_CONTAINERS，:50-103）

```ts
__nodeOptions[arrayField][i][childProp] = node   // 子节点嵌套在中间数组项的属性里
```

| arrayField | childProp | slotKey | 宿主 | removeMode | 说明 |
|---|---|---|---|---|---|
| `itemConfig` | defaultSlot | defaultSlot | YqFlexBox | set-null | 删子留壳（格子还在） |
| `tabPane` | defaultSlot | defaultSlot | TabPanel | set-null | 删子留壳（页签还在） |
| `buttonGroupOptions` | buttonOption | buttonOption | 按钮组 | splice-entry | 删子删壳（整个按钮项移除） |
| `columnSlots` | columRender | columRender | 表格族 | set-null | 删子留壳（列配置还在） |

每条规则附带 `createEntry(node, genTempId)` 工厂 —— 插入时若需新数组壳（新格子/新页签/新列）由它构造：

```ts
// tabPane 示例（:72-78）
createEntry: (node, genTempId) => ({
  renderType: "TabPanelItem",
  label: "新标签",
  name: genTempId(),
  paddingSize: "base",
  defaultSlot: node,
})
```

#### 形态 C：文档数组（DOCUMENT_ARRAYS，:106）

```ts
viewsProps.dialogOptions / drawerOptions / tabOptions
```

与 `planeOptions` 平级的**独立文档树**（对话框/抽屉不挂在平面树下），遍历与查找需单独走这三个数组。

> **历史问题（文件头注释）**：旧版 `SLOT_FIELDS` 扁平列表无法表达间接路径，导致 tabPane / buttonGroupOptions / columnSlots / dialogOptions 的子节点遍历缺失。间接容器规则表就是为了解决它。

### 2.2 统一操作函数

| 函数 | 行号 | 职责 | 消费方 |
|---|---|---|---|
| `forEachChild(node, visitor)` | :129 | 遍历直接+间接全部子节点 | schema 遍历/查找/大纲树 |
| `locateChild(opts, nodeId, …)` | :180 | 定位子节点位置（slotKey/index/swapArr） | moveUp/moveDown/删除 |
| `removeChildFromOpts(opts, nodeId, …)` | :218 | 移除子节点（按 removeMode 决定留壳/删壳） | 删除节点 |
| `insertChildIntoOpts(opts, slotKey, node, index, …)` | :263 | 向指定槽位插入子节点 | 插入/拖拽投放 |
| `getSlotChildrenList(opts, slotKey)` | :310 | 取指定槽位子节点列表 | 拖拽插入索引计算 |
| `getNodeSlots(node)` | :340 | 列出节点拥有的槽位（key+label） | 大纲树/属性面板 |

`insertChildIntoOpts` 对间接容器有**空壳优先**策略（:292-300）：itemConfig 已存在空格子（defaultSlot 为 null/undefined）时直接填充，不新建格子。

## 3. 渲染层：NodeRenderer 插槽执行

**文件：`assembox-desktop-next/src/components/render/assem-node-renderer.vue` + 各容器组件模板**

### 3.1 容器模板显式声明宿主身份

每个容器组件在渲染插槽时，都用 `<NodeRenderer>` 包裹并声明 `(parent, slotName)` 二元组：

```html
<!-- assem-yq-tool-bar.vue -->
<template v-if="toolSlots.length" #tool>
  <NodeRenderer
    v-for="(slot, idx) in toolSlots"
    :key="slot.__nodeId"
    :node="slot"
    parent="YqToolBar"
    slot-name="toolSlot"
  />
</template>
<template v-if="filterSlots.length" #filter>
  <NodeRenderer
    v-for="(slot, idx) in filterSlots"
    :key="slot.__nodeId"
    :node="slot"
    parent="YqToolBar"
    slot-name="filterSlot"
  />
</template>
```

### 3.2 嵌套门禁（nesting.ts SLOTS 表）

**文件：`assembox-desktop-next/src/components/nesting.ts:60-100`**（"谁能装谁"的唯一真相源）

```ts
export const SLOTS: Partial<Record<SlotHost, SlotMap>> = {
  // 视图层
  Plane:   { defaultSlot: ['layout', 'container'] },
  Dialog:  { defaultSlot: ['layout', 'container'] },
  Drawer:  { defaultSlot: ['layout', 'container'] },
  // 容器
  YqPanel:     { defaultSlot: ['layout', 'element', 'lineElement'] },
  YqBox:       { defaultSlot: ['layout', 'element', 'lineElement'] },
  YqToolBar:   { toolSlot: ['lineElement'], filterSlot: ['lineElement'] },
  TabPanel:    { defaultSlot: ['element', 'lineElement', 'layout'],
                 labelSlot: ['lineElement'] },
  // 布局
  YqFlexBox:   { defaultSlot: ['container', 'layout', 'element', 'lineElement'] },
  YqFlexLine:  { defaultSlot: ['lineElement'], rightSlot: ['lineElement'] },
  GridBox:     { defaultSlot: ['layout'] },        // 子必为 GridItem
  GridItem:    { defaultSlot: ['element', 'lineElement'] },
  // 表格/列表/…（表格单元格槽 TABLE_CELL: ['columnElement','lineElement']）
};
```

门禁语义：

- **类别数组** = 白名单（子组件 `category` 必须命中）
- **`'any'`** = 有意不限制（与"未登记"区分）
- **未登记** → `NEST_SLOT_UNDECLARED` 告警（dev 下），不拦截
- **白名单不中** → `NEST_CATEGORY_NOT_ALLOWED` 报错，**该子节点不渲染**（assem-node-renderer.vue:169-179）

注意：`SLOTS` 只登记 NodeRenderer 真正会执行的槽位。模板里硬编码直渲（如 Panel 的 toolSlot 直渲 `<FlexLine>`）不经 NodeRenderer，运行时不校验，故不在表内（nesting.ts:52-58 注释）。

### 3.3 节点协议与引用稳定约束

NodeRenderer 传给业务组件固定六件套（:138-148）：

```
__nodeOptions / __nodeEvent / __nodeStyle / __nodeProps / __nodeId / __nodeName
```

`normalizedNode`（:91-129）**刻意不克隆节点**：

> 克隆会让每次 computed 重算产生新引用 → 子组件 useNodeOptions 得到新 options 对象 → watcher fire → emit update:modelValue → 写回 $dataModels → useNodeOptions 重算 → **无限循环**。引用稳定是断开递归更新环的关键。

## 4. DOM 标记层：设计态打点

**文件：`assembox-desktop-next/src/composables/use-editor.ts`**

每个业务组件 setup 里调用 `useEditor()`，由 `isDesignMode()`（编辑器环境 + 非 preview）门控，onMounted 时在组件根元素打标记：

```ts
// use-editor.ts:94-96
const nodeId = (instance?.props as any)?.__nodeId;
if (nodeId) el.setAttribute('data-editor-id', nodeId);
```

同时：

- **剥离 disabled/readonly**（设计态组件必须可点，方案 A + MutationObserver 持续守护，Vue re-render 会重加属性）
- 挂载/更新/卸载回调上报 `window.AssemVueRenderer`（iframe 渲染器用）

标记属性常量：`src/designer/dom-marking.ts`

```ts
export const ATTR_EDITOR_ID = "data-editor-id";   // 节点根标记（唯一实际写入的标记）
```

**协议中还有两个槽位标记属性（读取端齐备，写入端缺失，见 §6）：**

- `data-slot-host="<宿主节点id>"` —— 该 DOM 区域属于哪个节点的槽位
- `data-slot-key="<slotKey>"` —— 具体哪个槽位

## 5. 拖拽识别层：canvas-sensor 命中链

**文件：`src/designer/drag/canvas-sensor.ts`**

### 5.1 findContainerEl 三级命中（:177-223）

从 `elementFromPoint` 的 target 沿 `parentElement` 逐层上爬，每层依次尝试：

```
① data-editor-id 命中
   └─ schemaOps.getNodeById(id) 存在 且 isContainer(node)
      → 返回 { id, slotKey: "defaultSlot" }            ← 当前实际主力路径

② data-slot-host + data-slot-key 属性
   └─ slotHost 节点存在
      → 返回 { id: slotHost, slotKey }                  ← 精确槽位（写入端缺失）

③ renderer.resolveFromElement 兜底
   └─ closest("[data-editor-id]") + closest("[data-slot-host]")
      → { nodeId, slotKey }                             ← renderer.ts:262-275
```

### 5.2 locate 全流程（:102-174）

```
elementFromPoint(target)
  → findContainerEl 三级命中（容器 id + slotKey + DOM 元素）
  → ①嵌套校验：nestingRules.canNest(parentRenderType, slotKey, childRenderType)
       （PcNestingRules 包装 nesting.ts lookupSlotGate —— 与渲染层同表）
       不过 → clearIndicator() + return null
  → ②后代拦截：拖已有节点时 isDescendantNode(containerId, dragNode.nodeId)
       防拖入自身/后代形成循环引用 → 拦截 + 清指示线
  → ③插入索引 computeInsertIndex（:234-291）
       getSlotChildren(parentNode, slotKey)         ← schema 侧子节点序列
       → 子节点实时 DOM rect（freshEl：renderer.getNodeElement 优先，
         querySelector 兜底，避免 re-render 后 stale ref）
       → detectMainAxis(rects)（:22-47）
           hRange > vRange × 1.2 → 水平主轴；否则纵向
           （用 max(bottom)-min(top) 而非首尾，防高度不一时误判）
       → 按主轴排序 → 光标与子节点中点二分比较 → rawIndex
       → isLayoutReversed 检测（:297-312）
           computedStyle.flexDirection === row-reverse / column-reverse
           → 视觉顺序与 schema 顺序相反 → index = len - rawIndex（翻转）
  → ④指示线 computeIndicator（:315-369）
       与插入索引共用 detectMainAxis（注释明言：杜绝"索引按水平算、
       指示线按垂直画"的方向矛盾）
       水平主轴 → 竖线（w=2, h=容器高）；纵向 → 横线（w=容器宽, h=2）
  → renderIndicator：画到画布文档 body（assem-drag-indicator）
  → 返回 DropLocation { containerId, region: slotKey, index, indicator }
```

### 5.3 投放执行（editor.ts wireDragon → onDrop，:258-314）

```
onDrop(dragObject, location)
  → 嵌套校验二次兜底（canNest，防漏）
  → dragObject.type === "nodeData"（组件面板拖新组件）
      → catalog.find(renderType) → schemaOps.createNode(scaffold 克隆)
      → insert(containerId, location.region, node, location.index)
  → dragObject.type === "node"（画布/大纲拖已有节点）
      → isDescendantNode 再拦一次
      → move(nodeId, containerId, location.region, index)
```

最终落地都走 `slot-accessors.ts insertChildIntoOpts`（§2.2）：

- 直接槽位 → 数组 splice 到 index
- 间接容器 → 空壳优先填充（itemConfig 空格子）→ 否则 createEntry 造新壳

大纲树拖拽同构（outline-pane.tsx:210-214）：`canNestInto` 校验 + `move(dragId, parentId, slotKey, index)`。

## 6. 已知缺口与建议（审查重点）

### 6.1 【已解决】多槽位组件的插槽识别（原 data-slot-host 只读不写缺口）

**原问题**：`data-slot-host`/`data-slot-key` 读取端三处齐备但无写入端，多槽位容器（Toolbar/TabPanel/FlexLine）拖拽一律退化为 defaultSlot，`getSlotMarkers` 恒空。

**解决方案（2026-08-24 落地，编辑器侧几何解析）**：借鉴旧版 `schemaBindSlot + bindSlotHandle` 表驱动思路，但升级为**悬停时解析、零 DOM 写入**：

- `src/scenarios/pc-desktop/slot-dom-rules.ts` —— `SLOT_DOM_RULES` 规则表（renderType → [{selector, slotKey}]，类名取自 element-plus-ui 源码）+ `resolveSlotKeyFromDom()` 几何解析器
- `ScenarioProfile.resolveSlotKeyFromDom` —— 场景可插拔声明（scenario/types.ts）
- `canvas-sensor.ts findContainerEl 命中①` —— 命中容器后调 `resolveSlotKeyFromDom(renderType, containerEl, hitEl)`，按 `region.contains(hitEl)` 判定槽位，null 回退 defaultSlot

对比旧版（mounted/onUpdated 写 expando 标记）的优势：无标记时机问题、re-render 天然跟随、渲染库零侵入（use-editor.ts 保持只打 data-editor-id）。已登记：YqFlexLine（左 defaultSlot/右 rightSlot）、YqPanel（内容 defaultSlot/工具 toolSlot）、YqToolBar（筛选 filterSlot/工具 toolSlot）。新增多槽位组件只需在规则表加一行。命中②保留 data-slot-host 读取作为外置标记兼容路径。

### 6.2 命中① 的 isContainer 依赖

命中①要求 `schemaOps.isContainer?.(node)` —— 需确认该判定覆盖全部容器 renderType（含文档数组里的 Dialog/Drawer），否则画布上这些区域拖放会穿透到根节点。

### 6.3 间接容器插入的空壳语义

`insertChildIntoOpts` 空壳优先仅对 `itemConfig` 硬编码（:292 判断 `arrayField === "itemConfig"`）。tabPane/columnSlots 永远新建壳。若期望"删空页签后再拖入复用该页签"，当前行为是**新增页签**——需确认是否符合产品预期。

### 6.4 DOCUMENT_ARRAYS 只在部分链路处理

`findNodeById`（renderer.ts:327-367）等编辑器侧遍历已处理 dialogOptions/drawerOptions/tabOptions；但需排查：拖拽命中后若 containerId 是 Dialog 内节点，`getNodeElement` 在 iframe 模式下能否取到（Dialog 未 open 时 DOM 不存在 → freshEl null → 插入索引恒 0，指示线画在容器左上）。
