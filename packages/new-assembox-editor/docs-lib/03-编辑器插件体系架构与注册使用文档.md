## 1. 设计目标与旧版对比

新版插件系统针对旧版 assembox-editor 的痛点重新设计，参考 amis-editor-core 的插件模型与 lowcode-engine 的骨架/插件分层：

| 旧版问题 | 新版方案 |
|---|---|
| `getEditor()` 全局单例 + `window.lc-assemGlobalBus` 多通道事件 | `createEditor()` 工厂多实例，插件上下文显式注入（`PluginContext`） |
| 插件注册分散、副作用不可回收（资源泄漏） | `contributes` 自动应用 + 自动反注册；`setup` 返回 `dispose` 统一回收 |
| 插件间无依赖表达、初始化顺序不可控 | `dep` 声明依赖 + **Kahn 拓扑排序**，`priority` 兜底 |
| 事件监听器泄漏、异常互相影响 | EventBus 集中管理 + 订阅返回退订函数 + 监听器异常隔离 |
| 静态注册（import 即全局生效） | **实例级注册**（每个 Editor 实例独立插件集），`disableBuiltin` 可关内置 |

核心设计原则：

1. **声明优先**：能静态声明的（setter/action/asset/骨架面板）放 `contributes`，自动注册/反注册，插件作者不需要写 setup 样板代码
2. **动态收敛**：需要时序/逻辑的写 `setup`，返回清理函数即可参与统一回收
3. **错误隔离**：单个插件 setup 失败只跳过自身（进 `failed` 集合），不影响其他插件
4. **能力显式**：插件能做什么完全由 `PluginContext` + Editor 门面公开 API 决定，无隐藏全局

## 2. 插件体系架构总览

```
                         ┌──────────────────────────────────────┐
                         │           Editor (门面/Facade)        │
                         │  createEditor() 工厂，支持多实例       │
                         └──────┬───────────────────────────────┘
                                │ 构造时 register，start() 时 activate
┌───────────────────────────────▼─────────────────────────────────────┐
│                        PluginManager（插件管理器）                     │
│                                                                      │
│  register(plugin, options)          实例级注册（同 id 按 priority 覆盖）│
│  activate(ctx, scene)               scene 过滤 → 拓扑排序 → setup     │
│        │                            → contributes 自动应用 → 钩子绑定  │
│  destroy()                          逆序回收（反注册 + dispose + 解绑）│

       │              │               │              │
       ▼              ▼               ▼              ▼
┌────────────┐ ┌─────────────┐ ┌──────────────┐ ┌──────────────────┐
│contributes │ │   setup()   │ │  事件钩子      │ │ build* 收集器      │
│(静态声明)   │ │ (动态逻辑)   │ │ before/after* │ │ buildPanels       │
│            │ │             │ │ Insert/Update │ │ buildToolbars     │
│ setters    │ │ 返回 dispose │ │ Delete/Move   │ │ buildContextMenu  │
│ actions    │ │ (资源清理)   │ │ (可拦截)       │ │                  │
│ assets     │ │             │ │               │ │                  │
│ skeleton   │ │             │ │               │ │                  │
└─────┬──────┘ └──────┬──────┘ └──────┬───────┘ └────────┬─────────┘
      │               │               │                  │
      ▼               ▼               ▼                  ▼
┌──────────────────────────────────────────────────────────────────────┐
│                      插件可访问的编辑器能力（经 PluginContext）          │
│                                                                      │
│  editor  ── Editor 门面全量 API（Schema/选区/场景/拖拽/快捷键/路由…）    │
│  store   ── 响应式状态 + 历史栈（Vue reactive + shallowRef）           │
│  bus     ── EventBus（preventDefault/stopPropagation/async pending）  │
│  di      ── DIContainer（token 类型安全解析，TOKENS.* 全部服务）        │
│  skeleton ─ 骨架布局（7 区域 × 4 形态，add/remove/浮动切换）            │
│  setterRegistry / actionRegistry / assetRegistry ─ 三大注册表          │
│  getPlugin(id) ── 跨插件协作（拿其他插件实例及其 options）              │
└──────────────────────────────────────────────────────────────────────┘
```

时序（一次完整的插件生命周期）：

```
createEditor(options)
  ├─ PluginManager 实例化
  ├─ 注册内置插件（除非 disableBuiltin: true）
  ├─ 注册 options.plugins（可带 options：[plugin, options] 形式）
  └─ （插件此时只登记，不执行任何代码）

editor.start()
  ├─ 构建 PluginContext（editor/store/di/bus/skeleton/三 registry/getPlugin）
  ├─ pluginManager.activate(ctx, platform)
  │    ├─ 1. scene 过滤（scene 含 "global" 或匹配当前 platform）
  │    ├─ 2. dep 拓扑排序（Kahn；循环依赖降级 priority 排序）
  │    ├─ 3. 依次 setup（收集 dispose；失败进 failed 跳过）
  │    ├─ 4. contributes 自动应用（注册进 registry/skeleton，记录反注册函数）
  │    └─ 5. 绑定 8 个 CRUD 事件钩子（camelize 映射到插件方法）
  ├─ bus.trigger(EDITOR_INIT) / store.setReady(true) / bus.trigger(EDITOR_READY)
  └─ keyboard.attach()

宿主使用编辑器 ...
editor.destroy()
  └─ pluginManager.destroy()（见第 12 章）
```

## 3. 插件契约（EditorPluginObject）

插件是一个满足 `EditorPluginObject` 契约的普通对象，推荐用 `definePlugin()` 工厂创建（提供类型推导 + 预留默认值注入扩展点）：

```typescript
import { definePlugin } from "@cs/assembox-editor-next";

export const myPlugin = definePlugin({
  id: "my-plugin",           // 必填，全局唯一
  // ... 其余全部可选
});
```

### 3.1 元信息字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `string` | **必填**。插件唯一标识；同 id 重复注册按 priority 覆盖（见 4.3）；也是 `dep`、`getPlugin(id)` 的引用键 |
| `name` | `string` | 显示名（调试/文档友好） |
| `description` | `string` | 描述 |
| `priority` | `number` | 排序优先级，**越大越先** setup。两个用途：① 拓扑排序同级排序；② 同 id 覆盖裁决（新 priority ≥ 已注册才覆盖，相等时后到者覆盖） |
| `scene` | `string \| string[]` | 激活场景过滤。不写 = 所有场景激活；包含 `"global"` 或匹配 `activate(ctx, scene)` 第二参（编辑器传 `platform`，即 `"desktop"` / `"mobile"`）才激活 |
| `dep` | `string[]` | 依赖的其他插件 id。激活时拓扑排序保证被依赖者先 setup；依赖未注册的 id 自动忽略 |

### 3.2 contributes —— 声明式贡献（静态自动注册）

`contributes` 在**所有插件 setup 完成后**统一应用，每项注册都会记录反注册函数，`destroy` 时自动逆序回收。插件作者无需写注册/清理代码：

```typescript
export interface PluginContributes {
  /** 注册 setter（属性编辑器），进 ctx.setterRegistry */
  setters?: SetterMeta[];              // { name, component }
  /** 注册声明式动作，进 ctx.actionRegistry */
  actions?: ActionMeta[];              // { actionType, title?, run, argsConfig? }
  /** 注册第三方 JS/CSS 资产，进 ctx.assetRegistry */
  assets?: AssetMeta[];                // { id, kind: 'js'|'css', url, ... }
  /** 向骨架布局贡献 widget，进 ctx.skeleton */
  skeleton?: SkeletonContribution[];
}
```

`SkeletonContribution`（骨架贡献，详见第 9 章）：

```typescript
export interface SkeletonContribution {
  area: "topArea" | "leftArea" | "leftFixedArea" | "leftFloatArea"
      | "centerArea" | "rightArea" | "bottomArea";
  type: "Widget" | "Panel" | "PanelDock";
  name: string;                        // widget 唯一名
  content?: any;                       // Vue 组件
  contentProps?: Record<string, any>;  // 自动追加 editor 注入（见下）
  panelProps?: Record<string, any>;    // PanelDock 面板参数（panelName/area）
  props?: Record<string, any>;         // Dock 图标参数（title/icon/align/description）
  disabledPanelCache?: boolean;
}
```

> **注意**：`applyContributes` 应用 skeleton 贡献时会自动向 `contentProps` 注入 `editor`（`contentProps: { ...s.contentProps, editor: ctx.editor }`），因此被贡献的面板组件**无需手动获取编辑器实例**，直接声明 `props: { editor: { type: Object, required: true } }` 即可。

### 3.3 setup —— 动态逻辑（可选）

```typescript
setup?: (
  ctx: PluginContext,
  options?: TOptions,      // 注册时传入的插件选项
) => void | Promise<void> | (() => void | Promise<void>);
```

- 按**拓扑顺序**依次执行（被依赖者先执行）
- 可以是 async；返回**函数**会被收集为 `dispose`，在 destroy 时逆序调用（资源清理：定时器、事件订阅、DOM 观察器等都要在这里回收）
- 抛错会被捕获并记入 `failed` 集合：该插件的钩子、build*、contributes 后续跳过，**不影响其他插件**

### 3.4 事件钩子（8 个 CRUD 钩子）

事件名 kebab-case 经 `camelize` 映射为插件方法名，由 PluginManager 自动绑定到 EventBus：

| 钩子方法 | 对应事件 | 触发时机（Editor API） | context 载荷 |
|---|---|---|---|
| `beforeInsert(ctx)` | `before-insert` | `editor.insert()` 前 | `{ parentId, slotKey, node, index }` |
| `afterInsert(ctx)` | `after-insert` | `editor.insert()` 成功后 | 同上（node 为创建后的节点） |
| `beforeUpdate(ctx)` | `before-update` | `editor.update()` 前 | `{ nodeId, patch }` |
| `afterUpdate(ctx)` | `after-update` | `editor.update()` 成功后 | 同上 |
| `beforeDelete(ctx)` | `before-delete` | `editor.remove()` 前 | `{ nodeId }` |
| `afterDelete(ctx)` | `after-delete` | `editor.remove()` 成功后 | 同上 |
| `beforeMove(ctx)` | `before-move` | `editor.move()/moveUp()/moveDown()` 前 | `{ nodeId, toParentId, slotKey, index }` 或 `{ nodeId, direction }` |
| `afterMove(ctx)` | `after-move` | `editor.move()` 成功后 | 同上 |

**拦截协议**（详见第 8 章）：返回 `false` → `preventDefault + stopPropagation`（操作被取消）；返回 Promise → 挂入 `event.pending`。钩子收到的是 `event.context`（载荷对象本身），不是事件对象。

### 3.5 build* 收集器（广播式扩展）

| 方法 | 调用时机 | 作用 |
|---|---|---|
| `buildPanels(node, panels)` | 选区变化 → `editor.rebuildPanels()` | 向右侧设置面板追加 `PanelItem`（Tab 页） |
| `buildToolbars(node, toolbars)` | 预留 | 向节点浮动工具栏追加 `ToolbarItem` |
| `buildContextMenu(node, menus)` | 预留 | 向右键菜单追加 `ContextMenuItem` |

node 为当前激活节点（可为 null），panels/toolbars/menus 为共享数组，插件 push 即参与渲染。

## 4. 插件注册

### 4.1 方式一：createEditor 传入（推荐）

```typescript
import { createEditor, definePlugin } from "@cs/assembox-editor-next";

const editor = createEditor({
  scenario: "pc-desktop",
  // 插件可带 options（元组形式 [plugin, options]）
  plugins: [
    myPlugin,                          // 无 options
    [myPanelPlugin, { defaultTab: 1 }], // 有 options
  ],
  disableBuiltin: false,               // true 则不注册 11 个内置插件
});

await editor.start();                  // activate 在此时才发生
```

Editor 构造函数内部逻辑（`src/core/editor.ts`）：

```typescript
if (!options.disableBuiltin) {
  for (const p of builtinPlugins) this.pluginManager.register(p);
}
for (const item of options.plugins ?? []) {
  Array.isArray(item)
    ? this.pluginManager.register(item[0], item[1])
    : this.pluginManager.register(item);
}
```

### 4.2 方式二：PluginManager 实例级 API

```typescript
editor.pluginManager.register(myPlugin, options);  // 注册（activate 前有效参与激活）
editor.pluginManager.unregister("my-plugin");      // 取消注册（仅 activate 前有效）
editor.pluginManager.getPlugin<MyOptions>("my-plugin");
// → { plugin, options } | undefined（仅返回已激活成功的）
editor.pluginManager.getPlugins();                 // 全部已激活实例
```

> `unregister` 在 activate 之后调用**不会**从已激活集合移除插件（只影响下次 activate），运行时移除见第 13 章 reload。

### 4.3 同 id 覆盖策略（priority 裁决）

```typescript
register(plugin, options) {
  const existing = this.registered.get(plugin.id);
  if (existing) {
    if ((plugin.priority ?? 0) < (existing.plugin.priority ?? 0)) {
      console.warn(`priority 较低，保留高优先级版本`);   // 拒绝覆盖
      return;
    }
  }
  this.registered.set(plugin.id, { plugin, options });  // ≥ 则覆盖（相等后到者胜）
}
```

典型用途：宿主用高 priority 插件**替换内置插件**（如自定义设置面板覆盖 `builtin-settings-pane`）。

## 5. 插件激活流程（PluginManager.activate）

`editor.start()` 内部调用 `pluginManager.activate(ctx, platform)`，五步流水：

### 步骤 1：scene 过滤

```typescript
const filtered = registered.filter(({ plugin }) => {
  const sc = plugin.scene;
  if (!sc) return true;                       // 未声明 = 全场景
  const arr = Array.isArray(sc) ? sc : [sc];
  return arr.includes("global") || arr.includes(scene);  // scene = platform
});
```

内置插件全部声明 `scene: ["global"]`；写 `scene: "mobile"` 的插件在 desktop 编辑器中不会激活（`getPlugin` 也查不到）。

### 步骤 2：dep 拓扑排序（Kahn 算法）

- 依赖了**未注册 id** 的边自动忽略（`if (idSet.has(dep))`）
- 入度为 0 的队列按 **priority 降序**出队 → 同级时 priority 大的先 setup
- 检测到循环依赖：告警并降级，剩余节点按 priority 排序追加（不卡死）

```
插件 A(dep: [B])、B、C → setup 顺序：B → C → A（B、C 同级按 priority 排）
```

### 步骤 3：依次 setup

- 依拓扑序执行 `plugin.setup(ctx, options)`，await Promise
- 返回函数 → 压入 `disposes`（destroy 时逆序调用）
- 抛错 → `failed.add(plugin.id)`，该插件后续钩子/build* 全部跳过，不影响他人

### 步骤 4：contributes 自动应用

遍历**所有**未失败插件（注意：failed 插件的 contributes 也会被应用，实现上遍历 `this.instances` 未过滤 failed——注册静态资产无副作用风险，但请避免在可能 setup 失败的插件里贡献 skeleton）：

| contributes 项 | 注册到 | 反注册 |
|---|---|---|
| `setters` | `ctx.setterRegistry.register(name, component)` | `setterRegistry.unregister(name)` |
| `actions` | `ctx.actionRegistry.register(meta)` | `actionRegistry.unregister(actionType)` |
| `assets` | `ctx.assetRegistry.register(meta)` | `assetRegistry.unregister(id, version)` |
| `skeleton` | `ctx.skeleton.add({...config, contentProps: {..., editor}})` | `skeleton.remove(name)` |

### 步骤 5：绑定事件钩子

对 8 个 CRUD 事件类型逐一检查：只要存在任一活跃插件实现了对应 camelize 方法，就 `bus.on(type, ...)` 订阅一次；触发时遍历活跃插件依序调用（细节见第 8 章）。订阅句柄存入 `unsubscribers`，destroy 时统一解绑。

activate 有**幂等保护**：重复调用直接告警忽略；需要重新激活用 `reload()`。

## 6. 插件上下文（PluginContext）

`activate` 时由 Editor 构建，`setup(ctx, options)` 第一个参数即是。它是插件访问编辑器全部能力的**唯一入口**（显式依赖，无全局查找）：

```typescript
export interface PluginContext {
  /** Editor 门面：全量高层 API（见第 7 章） */
  editor: Editor;
  /** 响应式 Store：状态 + 历史 + 选区 */
  store: EditorStore;
  /** DI 容器：token 化服务解析（跨层解耦） */
  di: DIContainer;
  /** 事件总线：订阅/触发编辑器事件 */
  bus: EventBus;
  /** 骨架布局管理器：add/remove 面板 */
  skeleton: Skeleton;
  /** 三大注册表 */
  setterRegistry: SetterRegistry;
  assetRegistry: AssetRegistry;
  actionRegistry: ActionRegistry;
  /** 跨插件协作：按 id 取已激活插件及其 options */
  getPlugin: <T = any>(id: string) =>
    { plugin: EditorPluginObject<T>; options?: T } | undefined;
}
```

| 上下文成员 | 典型用途 |
|---|---|
| `editor` | 一切 Schema 操作（insert/update/remove…）、选区、场景切换、拖拽 API、快捷键、路由 |
| `store` | 响应式读取 `state.activeId`/`state.designMode` 等；`commit()` 带历史地改 schema；`schemaRef` 做响应式依赖 |
| `bus` | 订阅全量 EVENT（不止 8 个钩子）：`selection-change`、`save`、`scene-change`、`history-change`… |
| `di` | `di.get(TOKENS.XXX)` / `di.when(TOKENS.XXX)` 异步等待服务就绪；插件也可注册自己的 token 供他插件消费 |
| `skeleton` | 运行时动态 add/remove widget（contributes 是静态声明，这里是动态补充） |
| `getPlugin` | 插件 A 取插件 B 的实例与 options（配合 `dep` 保证 B 已 setup） |

### DI Tokens（Editor 构造时自动注册）

```typescript
import * as TOKENS from "@cs/assembox-editor-next";  // export * as TOKENS

TOKENS.EDITOR           // Editor 实例
TOKENS.STORE            // EditorStore
TOKENS.BUS              // EventBus
TOKENS.DI               // DIContainer 自身
TOKENS.PLUGIN_MANAGER   // PluginManager
TOKENS.SETTER_REGISTRY  // SetterRegistry
TOKENS.ASSET_REGISTRY   // AssetRegistry
TOKENS.ACTION_REGISTRY  // ActionRegistry
TOKENS.SKELETON         // Skeleton
TOKENS.SELECTION        // Selection

// 用法
const store = ctx.di.require(TOKENS.STORE);        // 不存在则抛错
const sel   = ctx.di.get(TOKENS.SELECTION);        // 可能 undefined
await ctx.di.when(TOKENS.SETTER_REGISTRY);          // 异步等待注册完成
// 或经 editor 便捷方法：
ctx.editor.resolve(TOKENS.SKELETON);
```

插件也可注册私有 token（如状态共享）：`ctx.di.register(myToken, sharedState)`，销毁时随 `di.clear()` 一并回收。

## 7. 插件可访问的编辑器能力

插件通过 `ctx.editor`（或 DI tokens）可访问的能力全景。**这些 API 均为 Editor 公开成员，插件可全量调用**。

### 7.1 Editor 门面 — Schema 操作（带事件 + 历史 + 渲染器同步）

| API | 说明 | 触发事件 |
|---|---|---|

## 8. 事件钩子与拦截机制

钩子是「事件订阅」的语法糖：PluginManager 为 8 个 CRUD 事件各建一个总线订阅，触发时把 `event.context` 依序传给各活跃插件的对应方法：

```typescript
// 伪码（plugin-manager.ts bindEventHooks）
bus.on("before-delete", (event) => {
  for (const plugin of activeInstances()) {
    const fn = plugin["beforeDelete"];
    if (typeof fn !== "function") continue;
    const ret = fn.call(plugin, event.context);       // 注意：传 context
    if (ret === false) {                               // 拦截
      event.preventDefault();
      event.stopPropagation();
    } else if (isPromise(ret)) {
      event.pending.push(ret);                          // 异步挂起（不阻塞流程）
    }
    if (event.stopped) break;                           // stopPropagation 短路
  }
});
```

**拦截示例** —— 删除前确认：

```typescript
definePlugin({
  id: "guard-delete",
  beforeDelete({ nodeId }) {
    const node = editor.schemaOps.getNodeById(editor.store.schema, nodeId);
    if (node?.__nodeOptions?.renderType === "YqPanel" && !confirm("确认删除面板？")) {
      return false;   // editor.remove() 中 event.prevented → 取消删除
    }
  },
});
```

要点：

1. `before*` 返回 `false` = 阻止默认行为**并停止后续插件**；返回 Promise **不会**阻塞操作（仅记入 pending，如需异步拦截需自行在 promise 中同步返回 false 或改用 bus 直接订阅并同步 preventDefault）
2. 钩子异常被捕获打印，不中断其他插件
3. 插件也可以不经钩子、直接 `ctx.bus.on(EVENT.BEFORE_DELETE, (e) => e.preventDefault())`（拿到完整事件对象，控制更细）
4. `setup 失败` 的插件钩子不会被调用

## 12. 销毁与资源回收

`editor.destroy()` → `pluginManager.destroy()`，**逆序**三段回收：

```
1. 逆序 contributed 反注册：skeleton.remove / registry.unregister（后注册的先撤）
2. 逆序 setup dispose：插件清理自身资源（DOM/定时器/订阅）
3. 解绑全部事件钩子（unsubscribers）
随后重置：instances/failed 清空、activated = false
```

Editor.destroy 同链路还会：触发 `EDITOR_DESTROY`、dragon.destroy、keyboard.detach、liveEditing.dispose、renderer.dispose、bus.destroy、di.clear。

**插件作者守则：setup 里申请的每一份资源（DOM 节点、setTimeout、事件订阅、观察器）都要在返回的 dispose 里释放**；contributes 部分框架已自动回收，无需处理。

## 13. 动态增删插件

activate 之后的 `register/unregister` 不生效（激活集合已固化）。运行时变更需 `reload`：

```typescript
// 注册新插件 → 全量重激活（destroy 当前激活集 + 重新 activate）
editor.pluginManager.register(newPlugin);
await editor.pluginManager.reload({
  editor, store: editor.store, di: editor.di, bus: editor.bus,
  skeleton: editor.skeleton, setterRegistry: editor.setterRegistry,
  assetRegistry: editor.assetRegistry, actionRegistry: editor.actionRegistry,
  getPlugin: (id) => editor.pluginManager.getPlugin(id),
}, editor.store.state.platform);
```

代价：所有插件 setup/dispose 重跑、面板组件重建。**仅用于低频场景**（如插件市场安装）；高频 UI 变化应改用 `skeleton.add/remove` 动态挂载 widget，而非 reload。

## 14. 最佳实践

1. **id 命名**：业务插件用 `公司/项目-功能` 前缀（如 `yq-trace-panel`），避免与内置 `builtin-*` 及第三方冲突
2. **声明优先**：setter/action/asset/静态面板一律 `contributes`；setup 只做有时序的事（订阅、初始化、DI 注册）
3. **必返回 dispose**：setup 里任何副作用都要可回收，防止编辑器多次创建/销毁（SPA 路由进出）后泄漏
4. **改 schema 走 commit**：`ctx.store.commit("label", s => ...)` 或 Editor 高层 API，保证可撤销、渲染器同步
5. **响应式依赖**：组件里 watch `store.schemaRef`（不是 `store.schema`），监听字段用 `store.state.xxx`
6. **依赖显式化**：插件间协作用 `dep` + `getPlugin`/DI token，不猜加载顺序
7. **scene 标注**：桌面专属插件写 `scene: ["desktop"]`，通用写 `["global"]` 或不写
8. **错误自吞**：钩子/build* 内部 try-catch 期望之外的异常，避免影响其他插件（框架已兜底捕获，但会打 error 日志）
9. **自定义事件命名空间**：`bus.trigger("my-plugin:xxx")`，防与 EVENT 常量撞名
10. **不要缓存节点引用**：schema 会被 undo/redo 整体替换，跨帧持有 node 引用会 stale；始终按 `nodeId` 现查（`schemaOps.getNodeById`）

## 15. FAQ

**Q1：插件什么时候执行？为什么 register 后 setup 没跑？**
A：register 只登记。`editor.start()` 内 `pluginManager.activate()` 才执行 scene 过滤 → 排序 → setup → contributes → 钩子绑定。

**Q2：getPlugin 返回 undefined 的原因？**
A：任一情况：① 未 register；② 被 scene 过滤（scene 不含 "global"/当前 platform）；③ setup 抛错进 failed；④ activate 前调用（getPlugin 只查已激活集合）。

**Q3：beforeInsert 返回 Promise false 为什么没拦截？**
A：钩子的 Promise 只挂入 `event.pending` 不阻塞流程；需要拦截必须**同步**返回 `false`。异步校验请在拖拽链路（CanvasSensor/nestingRules）或 bus 直接订阅中同步 preventDefault。

**Q4：两个插件同 id 都注册了会怎样？**
A：后注册者 priority ≥ 前者 → 覆盖（后者生效）；更低 → 告警保留高者。内置插件 priority 100/200，业务覆盖用 1000+。

**Q5：插件能直接改 store.state.schema 吗？**
A：能改但不应该。绕过 commit 的修改：不进撤销栈、不触发 schemaRef 通知（面板不更新）、不同步渲染器。规范入口是 `store.commit()` 或 Editor 高层 API。

**Q6：contributes 的面板组件怎么拿到 editor？**
A：`applyContributes` 自动向 `contentProps` 注入 `editor`；组件声明 `props: { editor: Object }` 即可。也可 `inject("assem-skeleton")`（Workbench provide）拿骨架实例。

**Q7：插件能注册新的画布组件（物料）吗？**
A：物料目录由场景档案（`ScenarioProfile.componentCatalog`）提供，不走插件。扩展物料的正确姿势：注册自定义 ScenarioProfile（`registerScenario`），或在场景包内扩展 catalog；插件可配合 `assetRegistry` 注入组件运行时依赖。

**Q8：怎么在插件里加键盘快捷键？**
A：`ctx.editor.keyboard`（KeyboardManager）注册；或 setup 中自行 `window.addEventListener("keydown")` 并在 dispose 移除。参考 `hooks/use-editor-shortcuts.ts` 的用法。

**Q9：插件 setup 抛错会影响编辑器启动吗？**
A：不会。PluginManager 捕获后 `failed.add(id)`，该插件被跳过，其余照常；错误打印 `[PluginManager] 插件 "xxx" setup 失败`。

**Q10：事件钩子和直接 bus.on 订阅 BEFORE_* 有何区别？**
A：钩子收到 `event.context`（载荷），bus.on 收到完整 `EditorEvent`（可 preventDefault/stopPropagation/allDone）；钩子按插件激活序执行且随插件销毁自动解绑，bus.on 生命周期自负。
