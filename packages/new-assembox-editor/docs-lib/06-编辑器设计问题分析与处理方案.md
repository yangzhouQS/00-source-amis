## 2. P0：阻塞数据源闭环与正确性问题

### 2.1 SAVE 载荷不完整（#1）

**现状**：`save()` 仅 `bus.trigger(EVENT.SAVE, { schema })`（editor.ts:657-659）。uiSkeleton 之外，routerConfig 存于 `editor.router`、dataSource 存于 `editor.dataSource`，宿主拿不到 → **保存必然丢页面路由与数据源**。

**方案**（设计文档 05 §9.3 已承诺，未落地）：

```ts
save(): void {
  this.bus.trigger(EVENT.SAVE, {
    schema: this.store.schema,
    routerConfig: this.router.getRouterConfig(),
    dataSource: this.getDataSource(),   // 见 2.5
  });
}
```

同时 demo `main.tsx` 补 SAVE 订阅示例（当前 demo 无任何 SAVE 消费者，`Ctrl+S` 触发后无人接）。量级 S。

### 2.2 草稿范围不含 dataSource（#2）

**现状**：草稿 entry 仅 `{ v:1, ts, schema }`（editor.ts:571），且防抖由 `watch(store.schemaRef)` 驱动（editor.ts:413-417）。数据源面板 flush 只替换 `editor.dataSource` 引用，**不触碰 schemaRef** → 改了 20 个服务，刷新全部丢失，且与「草稿自动保存」的产品预期相悖。

**方案**：

1. entry 增补 `dataSource?`（读侧兼容：`entry.v === 1 && entry.schema` 已容忍多余字段）
2. 数据源 doc 的 flushNow 里，在替换 `editor.dataSource` 后调用 `editor.requestDraftSave?.()`；Editor 侧暴露 public `scheduleDraftSave()`（现 private）
3. `readDraft` 返回 `{ schema, dataSource? }`，start 时 `this.dataSource = draft.dataSource ?? options.dataSource`

量级 S。涉及 `core/editor.ts` + `plugins/data-source-pane/doc/use-data-source-doc.ts`。

### 2.3 画布 dataSource 热更新通道缺失（#3）

**现状**：全仓库 `setRuntimeConfig` 唯一出现点是插件里的乐观调用（`use-data-source-doc.ts:79`，`as any` + 可选链 = **静默 no-op**）。两条画布路径均在 mount 时定格 dataSource：

- inline `PcRenderer`：`AssemCore` 在 `app.use(AssemPlugin, config)` 构造，之后无人重建
- iframe `IframeCanvasRenderer.setRuntime` 存在但仅连接时生效，mount 后调用不触发重编译

**后果**：改数据源后画布 $requestFns/$dataModels/$sharedFns 仍是旧编译产物 —— 插件的核心价值（改完即见）落空。

**方案**（分两期）：

- **一期（粗粒度，复用现成装配链）**：`scenario/types.ts` IRenderer 增补可选方法 `setRuntimeConfig?(payload: { dataSource?; globalVars? })`：
  - `PcRenderer`：保存当前 schema → `unmount()` → 用新 dataSource 重新 `mount()`（代价 ~100ms，配置场景可接受）
  - `IframeCanvasRenderer`：更新 runtimeConfig 缓存 → `syncSchema(当前 schema)` + 重建 app
  - `PcIframeRenderer`：透传 `rendererApi.setRuntimeConfig?.(payload)`；协议 `IframeRendererApi` 加同名方法
  - 插件侧去掉 `as any` 改用正式接口
- **二期（增量）**：`AssemCore` 拆出 `reinitServices()`（仅重建 $dataModels/$requestFns/$sharedFns + re-provide），不动 Vue 树 —— 依赖渲染库改造，另立需求

量级 M。**这是数据源插件验收用例 1（改 url → 画布重新请求）的前置条件**。

### 2.4 Ctrl+Z 双重撤销冲突（#4，本 session 引入）

**现状**：`keyboard-manager.ts:49` 全局绑定 `Ctrl+Z → editor.undo()`（schema 历史）；数据源面板 `data-source-pane.tsx` 又在 window 上绑 `Ctrl+Z → doc.undo()`。**焦点在任何非输入元素上按一次 Ctrl+Z，两套历史同时回退**（比如正在画布上撤销拖拽，数据源也被回滚一步）。

**方案**（择一，推荐 A）：

- **A. 焦点域判定**：面板根容器加 `tabindex="0"`，keydown 监听改挂在面板根元素（capture 阶段）而非 window —— 只有焦点在面板内才走 doc.undo 并 `stopPropagation` 阻断 keyboard-manager；焦点在面板外（画布/其他面板）由 keyboard-manager 处理 schema undo。语义与两套历史的隔离设计一致
- B. 撤销上下文注册制：Editor 提供 `activeUndoScope`（面板 onMounted 声明 + onBeforeUnmount 注销，focus 事件切换），keyboard-manager 与面板都查它路由到对应历史 —— 更通用但改动大，留作二期

同时删掉现有 window 级监听。量级 S，**必须与 #3 同批修复**（否则数据源面板的撤销体验是错的）。

### 2.5 右键粘贴回退路径硬编码错误（#5）

**现状**（editor.ts:443-447）：

```ts
action: ({ nodeId, editor }) => {
  if (nodeId) editor.paste(nodeId);
  else if (editor.clipboard) {
    editor.insert(editor.store.schema.$$id ?? "root", "body", editor.clipboard);
  }
}
```

三处错误：① `schema.$$id` 在 pc schema 不存在 → 恒回退 `"root"` 字面量，而真实根 id 是 `YqFlexBox::root` 这类 → insertNode 找不到父节点静默失败；② slotKey `"body"` 不在 DIRECT_SLOTS 词汇表；③ 绕过了 `paste()` 已有的正确无参分支（getCurrentSceneRootId）。

**方案**：改为 `action: ({ nodeId, editor }) => editor.paste(nodeId ?? undefined)`。一行修复。量级 S。

顺带补一个单测：无选中时右键粘贴应调用 paste 的根分支（当前该路径零测试）。

## 3. P1：正确性与一致性缺陷

### 3.1 setter 数据供给未实现（#6）

**现状**：`element-table.ts` 等 10+ 处元数据已配 `setter: "RequestFnSetter"/"ModelNameSetter"`，但两个 setter 只读 props（`dataSourceTree`/`modelTree` 恒空）→ **渲染成空树**。settings-pane 已 provide `SETTER_CONTEXT_KEY`，两个 setter 未消费。

**方案**（设计文档 05 §10 已设计，未落地）：setter 内 `useSetterCtx()`，props 为空时从 `ctx.editor.dataSource` 构建选项树（computed 依赖 dataSource 引用替换自动重算）。RequestFnSetter 按 groupName 分组；ModelNameSetter 构建 `模型→表→字段` 三级树，fullPath = `模型.表.字段`（与 useInputValue 寻址一致）。补 2 个 setter 单测（构建树结构 + dataSource 引用替换后重算）。量级 M。

### 3.2 `store.batch()` 快照后置 bug（#7）

**现状**（store.ts:127-135）：

```ts
batch(label, mutator) {
  this.suspendHistory = true;
  try { this.commit(label, mutator); }   // commit 内跳过 pushHistory
  finally {
    this.suspendHistory = false;
    this.pushHistory(label);             // ← 此时 schema 已是「变更后」状态
  }
}
```

pushHistory 克隆的是**变更后**快照 → batch 后第一次 undo 恢复到 batch 后状态 = 视觉无变化但消耗一条历史。当前无调用者（`grep \.batch(` 零命中），属潜伏地雷。

**方案**：batch 开始前先 `pushHistory(label)` 再 suspend 执行 mutator：

```ts
batch(label, mutator) {
  this.pushHistory(label);               // 变更前快照
  this.suspendHistory = true;
  try { this.mutate(mutator); }          // commit 的 no-history 路径
  finally { this.suspendHistory = false; }
}
```

加单测：batch 后 undo 应恢复到 batch 前状态。或者，若确认短期无用，直接删除该方法（YAGNI）留 JSDoc 指引。量级 S。

### 3.3 粘贴/拖放到根容器的槽位适配（#8）

**现状**：`paste()` 无选中分支 `insert(rootId, "defaultSlot", cloned)`（editor.ts:645）。但 pc 场景根是 YqFlexBox，其子容器是 **itemConfig（间接容器）**——直接槽位表里没有 defaultSlot 的消费方，flex-box-assem.vue 只渲染 itemConfig 插槽 → 产出**不可见孤儿节点**（schema 有、画布无，大纲树里出现删不掉的幽灵）。

**方案**：`insert` 前按场景档案解析根的实际槽位：

1. `PcSchemaOps` 增加 `getDefaultInsertSlot(parentId)`：查 `nesting-rules` + `slot-accessors`，YqFlexBox 根返回 `{ slotKey: "defaultSlot", via: "itemConfig" }`（insertChildIntoOpts 已支持 itemConfig 建壳插入）
2. `paste()` 根分支与 canvas-sensor 根区 drop 共用该 API
3. 回归用例：YqFlexBox 根粘贴 Button → itemConfig 新建壳 → 画布可见

量级 M（含 slot-accessors 联动验证）。

### 3.4 草稿 watch 泄漏与 destroy 竞态（#9）

**现状**：

- `watch(...)` 句柄（动态 import 返回）未保存 → destroy 无法 stop（editor.ts:412-418）
- `beforeunload` 监听未移除（destroy 清单 editor.ts:519-536 无此项）
- 竞态：start() 中 `await import("vue")` 未 resolve 前 destroy() → watch 仍会挂上 → **销毁后的编辑器仍向 sessionStorage 写草稿**

**方案**：watch 句柄存成员 `private unwatchDraft?: () => void`；destroy 里 `this.unwatchDraft?.(); window.removeEventListener("beforeunload", ...)`（把匿名箭头提为成员方法）；destroy 后置 flag，watch 回调检查 `if (this.destroyed) return`。补单测：start→立即 destroy→修改 schemaRef→sessionStorage 无写入。量级 S。

### 3.5 引用检查读滞后数据源（#10，本 session 引入）

**现状**：`reference-scan.ts` 遍历 `editor.dataSource`（原始引用），而数据源 doc 的 flush 有 300ms 防抖——「改了绑定 → 立刻删模型」场景下，检查基于旧快照可能漏报引用。

**方案**：scan 函数签名改为接收 `DsDocument`（调用方传 `doc.state`），场景遍历仍走 `editor.store.schema`（schema 无防抖，安全）。量级 S。

### 3.6 场景名零校验（#11）

**现状**：scene-switcher 的 ElMessageBox.prompt 结果直接 `editor.addScene(value)`（scene-switcher.tsx:46）→ 场景名成为 `uiSkeleton` 顶层 key 与路由 name/path。中文、空格、重名、`constructor/__proto__` 均放行 → 路由注册失败或原型链污染（`schema[name] = ...` 赋值到 `__proto__` 的经典漏洞）。

**方案**：三层防御：

1. UI 层 prompt 加 `inputPattern: /^[a-zA-Z_][a-zA-Z0-9_]*$/`（与数据源校验器同一正则，抽到共享 `utils/identifier.ts`）
2. `editor.addScene(name)` 内核层校验：非法标识符/已存在 → ElMessage.warning + return false（当前返回布尔但无拒绝理由）
3. `Object.create(null)` 防御或 `Object.hasOwn` 判重在 store.loadSchema/inferInitialScene 的 key 遍历处

量级 S。

### 3.7 loadSchema 不同步路由（#12）

**现状**：schema-pane「应用」走 `editor.loadSchema(json)`（editor.ts:600-607）只写 store + renderer.setSchema。若 JSON 里增删/改名了场景，`routerConfig` 与 vue-router 注册表不刷新 → 场景切换器显示新场景但路由跳转 404。

**方案**：loadSchema 后调用路由同步（PcRenderer 的 `syncRouterRoutes` 逻辑上提到 EditorRouter 层或在 loadSchema 里 diff 场景集 → addRoute/removeRoute）；routerConfig 与 uiSkeleton key 不一致时 emit 结构化 warn（比照数据源校验器 issue 形态）。量级 M。

### 3.8 failed 插件 contributes 仍被应用（#13）

**现状**：PluginManager 的 `applyContributes` 遍历激活实例集合，未过滤 `failed`（设计文档 03 §5 已如实记录该实现细节）——setup 抛错的插件，其骨架面板/setter 仍然注册 → 「半死」插件（面板能点开，逻辑全坏）。

**方案**：`applyContributes` 跳过 `this.failed.has(id)` 的实例；若某插件 setup 失败但 contributes 里有不可缺的 setter（如核心注册插件），console.error 显式提示。补单测：setup 抛错插件的 skeleton 贡献不应出现在 skeleton.aggregated。量级 S。

## 4. P2：性能、健壮性与工程化改进

### 4.1 行内校验反馈（#14）

params-model / model-editor 的「添加字段」写入 `""` 空 key，错误只在保存时由校验器统一报出。改进：行内 el-input blur 时即标红（`:class="{ 'is-error': !row.fieldName }"`）+ 空占位提示；保存校验兜底不变。量级 S。

### 4.2 iframe 双通道同步（#15）

`update()` 先 `setSchema(structuredClone(全量))` 再 `updateNode(增量)`（editor.ts:698-702）。iframe 模式下每次属性编辑全量克隆+传输。方案：updateNode 连接正常时跳过 setSchema（增量失败由 iframe 侧返回降级信号再走全量）；undo/redo/loadSchema 保持全量。量级 S。

### 4.3 历史快照内存（#16）

全量 JSON 克隆 × 50 条，271KB 配置 ≈ 13.5MB 常驻。方案（渐进）：① 快照改存 `structuredClone`（比 JSON.parse/stringify 快 ~2-3 倍且保 Map/Set）；② 后续引入按场景分段快照（只克隆 activeScene 子树）。不建议现在上不可变数据结构（Immer/Patch），改动面大。量级 M。

### 4.4 选区双轨收敛（#17）

`core/selection.ts`（Selection 类：select/toggleSelect/isSelected…）与 `store` 的 select/toggleSelect/state.selectedIds 并存，Editor.select 转发 store，Selection 注册进 DI 但消费方寥寥。方案：Selection 降级为 store 之上的纯派生视图（只读 + 事件），写路径统一走 store；或干脆删除 Selection、DI token 移除。量级 S。

### 4.5 测试覆盖（#18）

现状仅 5 个测试文件。建议按风险排序补齐：

| 优先 | 目标 | 用例要点 |
|---|---|---|
| 1 | `schema-ops`（PcSchemaOps） | insert/move/remove/duplicate 在直接槽位+间接容器（itemConfig/tabPane/buttonGroupOptions/columnSlots）四类宿主上的矩阵；regenerateNodeIds 深层替换 |
| 2 | `slot-accessors` | locateChild 定位/removeChild 的 set-null vs splice-entry 语义；getNodeSlots 枚举 |
| 3 | `editor` 高层 API | paste 根分支（含 #5/#8 回归）、addScene 拒绝路径、save 载荷形状（#1 回归）、草稿恢复含 dataSource（#2 回归） |
| 4 | `canvas-sensor` | detectMainAxis 两方向插入索引；嵌套校验前置拦截 |
| 5 | e2e（`test/` 目前空壳） | Playwright：载入 single-table-scene → 拖入 Button → 改属性 → 保存三段校验 |

量级 L（分批）。

### 4.6 环境耦合与私有依赖（#19、#20）

- demo `main.tsx:93` `app.use(window.Vue3BizComponentsLibrary)` —— 改为条件存在才注册 + 控制台缺失警告，并在 README 写明该 demo 需要的宿主全局清单
- `public/@cs/assembox-desktop-next` 仅占位 package.json：makefile/脚本补「从 workspace libs 构建 UMD 拷贝」步骤（产物已验证可构建）
